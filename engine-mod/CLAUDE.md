## Purpose

`msm_runtime`: the Fabric mod that reads `msm/` definitions from every loaded mod jar and turns them into blocks, items and entities with component-driven behaviour. Java package `dev.mcsupermods.runtime`.

## Contents

- `build.gradle.kts`, `settings.gradle.kts` — Gradle, Kotlin DSL; `-Pmc=<mc>` (default `default_mc`) selects the Minecraft version (ADR 0038).
- `gradle.properties` — shared facts: `default_mc`, `mod_version`, Rhino, JUnit, `geckolib_compile_fallback_version_id`; its `minecraft_version`, `loader_version`, `loom_version` and `fabric_api_version` only mirror `versions/<default_mc>.properties` for `tools/check-deps` (the build fails if they differ).
- `versions/<mc>.properties` — per-version facts (ADR 0038 D1): `minecraft_version`, `loader_version`, `loom_version`, `fabric_api_version`, `geckolib_version` and `geckolib_modrinth_version_id` (both blank when no GeckoLib build exists: the bridge then compiles against the fallback jar and GeckoLib never runs), `minecraft_dependency` (the `fabric.mod.json` range; a snapshot needs the `-` form, such as `>=26.4- <26.5-`). The jar is `build/libs/msm_runtime-<mod_version>+mc<mc>.jar`.
- `src/mc/<mc>/java`, `src/mc/<mc>/gametest` — version overlays (ADR 0038 D2), added to the main and gametest source sets for the selected version only. They hold only seams, one implementation per version with the same class name: `registry/BlockSounds` (26.3 `SoundType`, 26.4 `block_sound_set` keys), `client/EntityRendererRegistration` (26.4 passes `BuiltInClientRegistries.ENTITY_RENDERER`), GameTest `BlockSoundCheck` and `EquipSoundCheck` (26.4 `Equippable.equipSound()` is an `Optional`).
- `src/main/java/dev/mcsupermods/runtime/`
  - `loader/` — `DefinitionScanner` (scan `msm/` in all mods; kinds `block`, `item`, `entity`, `effect`, `biome_addition`, `loot_addition`), `SoundScanner` (ADR 0057 D1, D2: `assets/<ns>/sounds.json` keys of mods with `msm/` or a `depends` on `msm_runtime`, `minecraft` skipped, sorted), `DefinitionParser` (pure; format, warnings, Codecs), `MsmCodecs` (`closed` rejects unknown struct keys), `StrictJsonOps`, `BlockDefinition`, `ItemDefinition`, `EntityDefinition` (`Sounds`: ambient, hurt, death, step, interval), `EffectDefinition`, `BiomeAdditionDefinition` and `LootAdditionDefinition` (closed, so an unknown key is an error; pools stay JSON), `BlockDefinition.ItemSettings` (closed; `components`), `MsmCodecs.nonEmptyList`, `LoadReport` (`sounds`, logged as `registered N sound event(s)`; `biomeAdditions`, `lootAdditions`).
  - `components/` — component records and Codecs aligned with `packages/schemas/mcdoc/msm/`; `Goal` (dispatch on `type`, decoded one by one). Items (ADR 0042, B181): `msm:armor` (`Armor`, `ArmorSlot`, `ArmorMaterialSpec` = vanilla `ArmorMaterialName` or `CustomArmorMaterial`), `msm:tool` with `ToolTierSpec` (vanilla `ToolTier` or `ToolMaterialSpec`) and optional `attack_damage`/`attack_speed`; `MsmCodecs.nameOrObject` decodes the string-or-struct unions, `TAG_ID` the `#`-prefixed tag references. `MsmRegistrar.armor` calls `humanoidArmor(material, type)`, `tool` builds `new ToolMaterial(...)` for a custom tier; `enchantment_value: 0` removes `enchantable` (vanilla rejects 0); two of `msm:tool`, `msm:armor`, `msm:ranged_weapon`, `msm:shield` on one item are an error and none applies. Gear (ADR 0044, B187): `msm:consumable` (`food(FoodProperties, Consumable)` or `consumable`, `use_cooldown`, delayed `use_remainder`), `msm:ranged_weapon`, `msm:shield` (delayed `blocks_attacks` on a plain `MsmItem`), `msm:death_protection`, tool types `spear` (`SPEAR_CONSTANTS` from vanilla) and `mace`, armour slots `horse`/`wolf`, `msm:components` (`ComponentPassthrough`: static `RegistryOps`, `DELAYED` list through `delayedComponent`, else a load error), action `apply_effect` (`EventContext.other`). Effects and throwables (ADRs 0055, 0056, B203): `EffectComponents` (`msm:on_start`, `msm:on_tick` with `interval(amplifier)`, `msm:on_end`); `msm:throwable` (`ItemComponents.Throwable`, `AfterThrow`); `throwableConflicts` drops the throwable and `msm:armor`, `msm:ranged_weapon`, `msm:shield`, `msm:consumable`, `msm:food` or a `mace` tool together ("none is applied").
  - Triggers (ADR 0061, B235): closed trigger structs in `ItemComponents` (`OnHit`, `OnUseOnBlock`, `WhileHeld` with `HeldHand`, `WhileWorn`; `while_worn` without `msm:armor` is a load error and is dropped), `BlockComponents` (`OnBreak`, `OnPlace`, `OnRandomTick`, `OnEntityInside`) and `EntityComponents` (`OnTick`, separate from the effect's, and `OnSpawn`). `MsmItem` statics `hurtEnemyWithEvent` (hooks `hurtEnemy`, not `postHurtEnemy`: vanilla calls only `hurtEnemy` for a mob's or spear's hit), `useOnWithEvent` (as `useWithEvent`; a consumed click skips `use`), `inventoryTickWithEvent` (a `null` slot never fires; a player's main hand comes only from `Inventory.tick`), called by every item class; `MsmBlock` overrides `playerWillDestroy`, `setPlacedBy`, `randomTick` (`randomTicks()` set by the registrar only with the component), `entityInside`; `MsmEntity` overrides `customServerAiStep` and `finalizeSpawn`. Interval triggers fire when `(game time + entity id) % interval == 0`; `events/TickLimiter.SHARED` caps tick-trigger firings at 2,000 per server tick and logs skips once a minute; `events/CooldownMap` (bounded) holds the step and inside cooldowns.
  - `events/` — `Action` (dispatch on `type`, incl. `run_script`, `damage` (magic) and `heal`), `Events` (per-event decoding), `EventRunner` (depth 16; `livingTarget` resolves `self`/`other`), `EventContext` (`source` for `run_function` and sounds; `forBlockStep` (ADR 0058 D1): the stepper, player or any entity, is self and, when living, other, and runs functions as `@s`; `forEffect`: the holder is self and other; `forThrownHit`: self the thrower, other the entity hit; `forBlockActor` (placer or entity inside), `forItemHit`, `forItemUseOn`, `forHolder`; an item event without a player runs functions as its mob), `AnimationTarget`.
  - Block shapes (ADR 0059 D3, B225): `BlockComponents.Shape` (closed; `preset` is editor-only and an error; `seeThrough()` defaults as the plugin's `isSeeThroughBlock`); `MsmBlock` builds one `VoxelShape` (`Shapes.or` of `Block.box`, each axis ordered) for `getShape`, `MsmBlock.shapeProperties` adds `noCollision()` for `collision: false` and, for see-through, `noOcclusion()` with never suffocating, view-blocking or redstone-conducting; see-through also overrides `propagatesSkylightDown`, `getShadeBrightness` (1), `getVisualShape` (empty) and `skipRendering` against itself. No render-layer code: cutout and translucent come from the texture.
  - `registry/` — `MsmRegistrar` (sound events first, then effects, blocks, items, entities, additions; `LoadReport.effects`), `MsmEntityRegistrar`, `BiomeSelection` (the `#tag`-or-id union selector shared by natural spawns and biome additions), `MsmAdditions` (ADR 0060: one Fabric modification per feature or spawn, which looks the placed feature or entity type up first because Fabric's `addFeature` throws for a missing key; late warnings after start; loot pools decoded with `LootPool.CODEC` on every `MODIFY` for built-in sources only, one error per broken pool per load, `lastLootLoadErrors`), driver classes `MsmBlock` (step cooldown keyed by dimension, position and entity), `MsmItem` (`useWithEvent` shared by `MsmBowItem`, `MsmCrossbowItem`, `MsmMaceItem`, `MsmThrowableItem`), `MsmEntity` (mob sounds: the configured event when registered, else vanilla's), `MsmMobEffect` (`on_start` from `onEffectAdded`; `on_tick` and `on_end` (Fabric `ServerMobEffectEvents.AFTER_REMOVE`, which also fires on expiry) queued to `END_SERVER_TICK`, because vanilla calls them while iterating the holder's effect `HashMap`), `MsmThrowableItem` (`ProjectileItem`, dispenser behaviour when `dispensable`), `MsmThrownItem` (`msm_runtime:thrown_item`, registered always; snowball size, tracking range and update interval); GeckoLib only in `MsmGeoEntity` behind `GeckolibEntities` (touched after `isModLoaded("geckolib")`).
  - `goals/` — `FollowTypesGoal`. `client/` — `MsmRuntimeClient` (client entrypoint; vanilla `ThrownItemRenderer` for the thrown item always, GeckoLib renderers only with GeckoLib), `GeckolibRenderers`, `MsmGeoModel`.
  - `scripting/` (ADRs 0031, 0032) — `ScriptHost` (per server: load on `SERVER_STARTING`, reload on `END_DATA_PACK_RELOAD`; sealed shared standard objects, a scope per script, `require` of `msm:runtime` and relative ids, schedules, rate-limited errors, off-hand suppression), `ScriptBridges` (Fabric events; a cancelled player event resyncs the client, ADR 0058 D3: the inventory, plus the six neighbours for `block.interact`), `ScriptApi` (the `msm` tree and `describe()`), `ScriptType`/`HostObject` (read-only wrappers), `ScriptWorld` (`runCommand`/`runFunction` with an optional `at`), `ScriptEntity` (`runCommand`, `runFunction` as and at the entity), `ScriptPlayer`, `ScriptPos`, `BlockRef`, `ItemRef`, `ScriptEvents`, `MsmContextFactory` (sandbox, 2000 ms budget), `ScriptScanner`.
- `src/test/` — JUnit 5 over `../packages/schemas/mcdoc/msm/conformance/definition/`; `ScriptApiContractTest` reads `../packages/plugins/scripting/api/script-api-v1.json` in place.
- `src/gametest/` — Fabric GameTests; `resources/msm/msm_test/` holds the kitchen-sink definitions and hand-written ES5 scripts (`script/`), `assets/msm_test/geckolib/` a test model, `data/msm_runtime_gametest/gametest/structure/arena.snbt` the movement arena.
- GeckoLib (ADR 0029 D6): Modrinth Maven `exclusiveContent`; `compileOnly` + `gametestCompileOnly` + `localRuntime`; never in the jar, only `suggests` in `fabric.mod.json` (left empty for a version without GeckoLib).
- `parity/` — the parity GameTest build (ADR 0033 D5): same `-Pmc` handling over `../versions/` (default `../gradle.properties` `default_mc`), overlay `parity/src/mc/<mc>/java` (`ParitySounds`), `ParityEars` (sound observation), `SampleScriptParityTest`, jar `msm_parity_tests-<version>+mc<mc>.jar`; its `gradle.properties` Fabric keys only mirror this folder's.

## Conventions

- Java 25; Mojang names only (no Yarn, no Parchment).
- Fabric Loom 26.1+ non-remapping variant (verify at implementation).
- Fabric API events over Mixins; every Mixin needs a justification comment.
- Definitions parsed via Codecs aligned with MSM mcdoc; a schema change updates the Codecs and the corpus together.
- Registries are touched only during init; reloadable data stays in data packs.
- The script API grows only through `script-api-v1.json` first; the contract test fails until `ScriptApi` matches.
- Log with the mod-id prefix; no reflection on definitions.
- Versions: shared code never names a class that exists in one Minecraft version only; a difference goes behind a seam in `src/mc/<mc>/` (every version implements every seam), and a call that compiles on every version (such as the six-argument `Block.getDrops`) needs no seam. Adding a version: `versions/<mc>.properties`, the overlay folders, a CI matrix entry.
- Every session: append an entry to `docs/DEVLOG.md` (`## YYYY-MM-DD — <agent> — <topic>`, then What / Decisions / Next).

## Do / Don't

- Do keep the runtime free of any app dependency; it must work with hand-written `msm/` files. Don't hardcode content. Don't add Kotlin.

## Commands

- `JAVA_HOME=<jdk 25> ./gradlew build` (default version, runs JUnit and the GameTests); `./gradlew build -Pmc=26.4` for another version (the jars of both stay side by side in `build/libs/`)
- `./gradlew test` (JUnit only; the corpus test reads the schemas package in place); `./gradlew runGameTest` (headless GameTest server; `-PwithoutGeckolib` runs without GeckoLib) / `./gradlew runClient`; both take `-Pmc`
- `./gradlew -p parity build [-Pmc=<mc>]` (the parity GameTest jar)
- CI job `engine-mod` is a matrix over the versions (`.github/workflows/ci.yml`; keep it equal to `versions/`)
