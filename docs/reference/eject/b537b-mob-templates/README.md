# Mob templates of the Java eject (B537b)

`gen-mob-templates.py` turns the runtime's habit, phase, bucket and storage classes (`engine-mod/src/main/java/dev/mcsupermods/runtime/registry/mob/MobHabits.java`, `MobStorage.java`, `MobBuckets.DryBucketItem`, and `goals/SwoopGoal`, `RoostGoal`, `CollectItemsGoal`, `DigForItemsGoal`, `PlayDeadGoal`, `BarterGoal`, `PhaseChargeGoal`) into the eject's templates in `packages/targets/mc-26.3/src/java-project/templates/mob-habits-java.ts`: the runtime's `MsmMob` adapter and parsed records give way to constructor arguments and the plain records `HabitGoal` and `MobStorage.Storage`, `MobMovement` to `PhaseChargeGoal.Charging`, and the runtime's logger to the mod's. `HoverMoveControl` and the boat classes (`templates/hover-move-control-java.ts`, `templates/boats-java.ts`) were written by hand from `MobMovement`, `MsmBoats` and `client/boat/BoatRenderers`.

`packages/targets/mc-26.3/test/java-project/boats-and-mobs.test.ts` compares every one of these classes line by line with the runtime (`MIN_SHARED` 0.75; measured 0.82 to 1.00). When a runtime class changes, that test fails: run the script from the repository root (`python3 docs/reference/eject/b537b-mob-templates/gen-mob-templates.py`), then `npx biome check --write` on the template, or edit the template by hand. Kept for reference only: not built, linted or run by CI.
