## Wave A

### B170 — `@msm/ai`: protocol, tools, loop, scripted client, SDK adapter (lockfile owner)

**Owns:** `packages/ai/` (new), `tools/check-deps/layers.json` (one entry), root `tsconfig.json` (one reference), `pnpm-workspace.yaml` (the `@anthropic-ai/sdk` catalog entry), `pnpm-lock.yaml`, `biome.json` (one override), `app/package.json` (adds `"@msm/ai": "workspace:*"`; nothing else). Must not touch `app/src/**`. Everything but the four shared files is new.

**Purpose:** everything of ADR 0041 that runs without Electron, testable with Vitest, shared by main and renderer.

**Scope:**

1. Package scaffold as the other packages (`package.json` name `@msm/ai`, `private`, `type: module`, `exports` `.` and `./sdk` pointing at `src/`, scripts `test`/`typecheck`, `tsconfig.json` with project references to `@msm/plugin-api`), `README.md` (what it is, the two entry points and why, how to write a model script). Layer entry `"@msm/ai": ["@msm/plugin-api"]`; Biome override for `app/src/renderer/**` and `app/src/preload/**`: `noRestrictedImports` of `@anthropic-ai/sdk`, `@anthropic-ai/sdk/*` and `@msm/ai/sdk` ("the Claude SDK runs only in main, ADR 0041 D2"). Catalog `@anthropic-ai/sdk` pinned to the newest version at least two weeks old at implementation (`1.4.0` as of 2026-11-05; `1.5.0` from 2026-11-18; record the choice).
2. `src/protocol.ts`: the types and zod schemas of the fixed names (`AiSettings`, `AiStartRequest`, `AiToolRequest`, `AiToolResult`, `AiEvent`, `AiUsage`, `AiDoneReason`, `AiRunLimits`, defaults). `src/models.ts`: `AI_MODELS` with the facts table's prices and `checkedOn: '2026-11-05'`, `estimateCost`, `formatCost` ("about $0.12"). `src/tools/`: one file per group, `catalogue.ts` with `TOOL_CATALOGUE`, `toolParams()` (JSON Schema from `z.toJSONSchema` with `additionalProperties: false` on every object, no `$schema` key; verify what the API accepts and strip what it does not; `eager_input_streaming: true` on each), `parseToolInput(name, input)` returning the typed input or a zod error. Descriptions are the model's instructions per tool (when to call it, what it returns, the batch sizes); write them for a model that has never seen MSM: name the kinds that need the Fabric jar, the `msm:mod` singleton, placeholder textures, "run `run_checks` after every batch".
3. `src/system-prompt.ts`: `systemPrompt(mode)`: who the helper is (an assistant inside MCSuperMods, a mod maker for Minecraft Java whose projects are typed elements validated against the game's schemas), the rules (propose through tools, never claim to have applied anything, every id `namespace:path`, read the schema or a template before inventing data, check after every batch, keep answers short, British English, no emojis), the build-mode procedure of ADR 0041 D6 (plan first through `propose_plan`, dependency order, batches, `run_checks`, `checkpoint` after each item, a closing summary). ## Risks

- **SDK method shapes.** The beta features (`fallbacks: 'default'`, `task_budget`) are read from the skill, not from the installed package; B170 verifies against `node_modules` and records the shapes. If a beta is refused by the installed SDK's types, the request is built with the SDK's `extra_body`-style escape (name to verify) rather than a raw `fetch`.
- **Tool input validation with eager streaming.** The server does not validate inputs when `eager_input_streaming` is on; every input goes through zod before anything runs (B170) and again through the executor's semantic checks (B172).
- **Long build runs.** 150 tool turns with 600,000 output tokens is a long, costly run; the plan is shown first, the usage line updates per turn, Stop is one click, and the limit message tells the user how to continue. The ADR's defaults are a starting point: the user may want lower ones.
- **Session refactor.** `checkProject` touches the validation path of every element; B172 keeps `#validatePending`'s behaviour under the existing tests and adds the comparison test over `fixtures/sample-mod`.
- **Size.** The SDK adds about 0.4 MB to the asar as a lazy chunk (29.3 of 32 MB today); B171, B173 and B174 report `check-size`.
- **Scripted tests versus the real model.** Scripts prove the plumbing, not the model's behaviour; the real adapter is exercised by hand once before the release (the orchestrator notes the result in the ADR Status) and by the optional local-stub test.
- **Thinking blocks are model-bound.** A model change starts a new conversation; the controller enforces it (B173).
