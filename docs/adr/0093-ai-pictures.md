# ADR 0093: AI pictures

## Context

The user asked for AI art ("Yes add the ai art for now"): textures made by an image service from a description, then cleaned up into Minecraft style. MSM already has the pieces around it: the AI helper keeps the user's own Anthropic key encrypted in main and never gives it to the renderer ([ADR 0041](0041-ai-helper.md) D1); Picture to texture turns any picture into a texture by cropping, scaling, cutting the background and reducing colours ([ADR 0048](0048-pictures-screenshots-and-skins.md)); and asset writes are undoable ([ADR 0045](0045-undoable-asset-writes.md)). Anthropic's models do not draw pictures, so another service is needed, again with the user's own key. Another agent is prototyping a vanilla-style colour ramp generator (branch `art`, possibly ADR 0092 "Minecraft-style art"); this ADR does not depend on it.

## Decision

- **D1 Keys and settings.** A new Settings section **AI pictures**: choose the image service, paste its key, **Save key**, **Test key**, **Clear key**. Each service has its own key file, `<msmHome>/ai-pictures-<service>-key.bin`, written by the AI helper's key store (`createAiKeyStore` with a `fileName`): Electron `safeStorage`, refused when encryption is unavailable (on Linux, the `basic_text` backend counts as unavailable). The chosen service is not a secret and lives in `<msmHome>/ai-pictures.json`. The renderer sees whether each key is set and its last four characters only; the IPC contract's status schema has no room for a key. The section says plainly what is sent: the description (and the style), never project files.
- **D2 Services.** Adapters in main behind one interface, `generate({ prompt, style, size, count, transparent }) -> PNG bytes[]` and `testKey()`, each given the key, a `fetch` and an `AbortSignal`:
  1. **Retro Diffusion** (default), the pixel-art specialist. Chosen over PixelLab and the Replicate models because its public API has two Minecraft styles, `mc_texture` (tileable block textures) and `mc_item` (items), takes a bring-your-own key, has a free cost check and a free credits call (for **Test key**), and is cheap: RD Plus is $0.06 a picture, RD Fast $0.03 (official examples, `github.com/Retro-Diffusion/api-examples`, read 2026-11-14). Request: `POST https://api.retrodiffusion.ai/v2/inferences` with `X-RD-Token`, an `Idempotency-Key`, and `{ prompt, prompt_style, width, height, num_images, remove_bg, tile_x, tile_y }`; V2 queues the task, polled at `/v2/inferences/tasks/{id}` until `succeeded` (`result.base64_images`). MSM asks RD Plus (`rd_plus__mc_texture` for blocks with `tile_x` and `tile_y`, `rd_plus__mc_item` for items and tools with `remove_bg`) at four times the texture size within RD Plus's 64 to 384 pixels. The exact size limits of the `mc_*` styles come from `GET /v2/styles/selector`, which needs a key (verify at implementation). PixelLab's API has moved between `v1` and `v2` paths and has no Minecraft style; Replicate adds a second account and model versions to pin.
  2. **OpenAI Images**: `POST https://api.openai.com/v1/images/generations`, `Authorization: Bearer`, `{ model, prompt, n, size: '1024x1024', quality: 'low', background, output_format: 'png' }`, answers in `data[].b64_json` (developers.openai.com reference, read 2026-11-14). The model is `gpt-image-2.6-flare`, the guide's fast everyday model, which supports transparent backgrounds (verify at implementation); OpenAI publishes token prices for it ($30 per million image output tokens), not a price a picture. The model has no Minecraft style, so main appends style words (one square tileable block texture, or one item or tool icon, chunky pixel art, limited palette, light from the top left).
  The description the user edits names the subject only (Retro Diffusion's guide says not to write "pixel art"); each adapter adds its own style.
- **D3 Requests.** Every request has a time-out of 180 seconds (OpenAI says up to two minutes), a cancel by request id, and one of ten plain error classes: `no_key`, `bad_key` (401, 403), `quota` (402, `not_enough_balance`, `insufficient_quota`), `rate_limit` (429), `refused` (`moderation_blocked`, content refusals), `network`, `timeout`, `cancelled`, `server`, `bad_response` (not a PNG, nothing back). Messages never carry the key. Requests go out from main only, with the global `fetch`.
- **D4 Clean-up.** A pure pipeline in the renderer (`components/ai-pictures/cleanup.ts`) turns any picture into a Minecraft-style texture: items and tools lose their background (by the picture's own alpha when it has some, else by an edge flood over the corners' colour, Picture to texture's `removeBackground`), are cropped to their content and fitted into 16 by 16 or 32 by 32 keeping their proportions (one pixel short of each edge for the outline); blocks take the largest centred square. Downscaling takes the commonest colour of each area for pictures that are already pixel art and the alpha-weighted area mean otherwise, never a bilinear blur. Colours are quantised per hue cluster (up to three, plus the greys) to a ramp of N shades (default 6) by lightness rank, the dark end turned towards blue and the light end towards yellow. The rank is kept, so shading is never inverted: the light stays where the picture had it, and the prompts ask for the top left. Items and tools get a one-pixel outline darker than the darkest shade. The quantiser keeps the rank order but takes its shades from the drawn art's ramps (amended at the art batch's close, B502, after B498): each lightness group of a hue cluster gets a shade of `generateRamp` of the cluster's colour at the middle group's lightness, with `ART_HUE_SHIFT` (12 degrees, [ADR 0092](0092-minecraft-style-art.md) D8 and D15), at most 8 shades a ramp, so AI and drawn pictures share one palette rule.
- **D5 Make with AI.** A dialog with the description prefilled from the thing's name, kind and theme (editable), the style (**Minecraft block texture**, **Item icon**, **Tool**), the size, and **Make 4**: four pictures, each shown as the service drew it and after the clean-up. **Use this picture** hands the cleaned-up PNG to the host. A running request can be cancelled.
- **D6 Where it appears.** **Make with AI** sits on the picture fields: the Block Studio (a row per project texture of the block's model, and each texture slot of a typed block; an empty slot gets a new texture `textures/block/<name>_<slot>.png` and names it, in the same step), the Item Studio (the item model's project textures), the Particle Studio's frames, the Creator's image fields (except mob skins, whose 64 by 64 layout is not one picture) and the texture painter. A pick is written as one undoable step: over an existing asset as an asset write (ADR 0045), a new one as an asset change item; in the painter it replaces the canvas as one painter undo step and is saved with **Save**. Without a key for the chosen service the button reads **Set up AI pictures in Settings** and opens Settings; without main's services (tests) it is not shown. In Very easy mode it reads **Make it with AI**.
- **D7 Creator and Surprise me.** With a key set, the Creator and "Surprise me" show a **Use AI pictures** switch, off by default. Nothing is sent until **Create** or **Make it**; then each block and item texture the change items add is made with one request (the theme or name in the description), with progress and **Stop**. A texture whose request fails keeps the built-in picture; the message after making says how many were made and why any kept the built-in art. Everything is still one undo step.
- **D8 Tests.** Adapters with a mocked `fetch` (bodies, headers, polling, every error class, not-a-PNG); the service with a fake `safeStorage` (encrypted per-service files, only the tail in the status, the contract refusing a whole key, cancel, time-out, the IPC handlers); the pipeline on synthetic pictures (a photo-like shaded ball on a noisy background becomes a 16 by 16 icon with transparency and at most N colours, kept proportions, the outline, the light kept at the top left, monotonic ramps, two hue clusters, pixel art scaled by mode); the UI flows with a fake service (hidden without a host, Settings without a key, Very easy wording, four pictures before and after, the pick, cancel, errors, the switch, the batch's fall-back and stop). e2e `ai-pictures-path` runs with `MSM_E2E_AI_PICTURES_FAKE=1`, a fake service in main that needs no key and no network: a block made with the Creator, **Make with AI**, a pick, the texture changed on disk, one Undo.
- **D9 The AI helper.** No `generate_picture` tool for now. The helper's tools run in the renderer against the session, its catalogue is pinned by a hash, and a picture tool would spend the user's image credits from inside a model's plan; that needs its own decision (when to ask, how many pictures a run may make).

## Consequences

- MSM can make textures from a description with a service the user pays directly; nothing changes without a key.
- Two more key files in the MSM home folder; the AI helper's key store gains a file name option.
- Seven new IPC channels under `msm:v1:aiPictures:*`.
- The clean-up's quantiser uses the drawn art's ramps (`generateRamp` and `ART_HUE_SHIFT`, ADR 0092 D15) since B498.

## Status

Proposed (2026-11-14); D4 amended 2026-11-22 (B502) to the ramps it uses since B498. Defaults the user may veto: Retro Diffusion as the default service with RD Plus (D2); OpenAI's `gpt-image-2.6-flare` at low quality (D2); six shades a hue and the blue and yellow turn (D4); the outline on items and tools by default (D4); four pictures a round (D5); no skins (D6); the switch off by default (D7); no AI helper tool (D9).
