# ADR 0094: The remaining vanilla block types, waterlogging and weathering

## Context

[ADR 0067](0067-block-types-and-states.md) and [ADR 0068](0068-crops-saplings-trees-and-leaves.md) gave `msm:block` 17 types and deferred the rest (ADR 0067 D11, ADR 0068 D9): beds, cakes, berry bushes, double plants, ladders, torches, lanterns, chains, signs and hanging signs, flower pots, waterlogging for plain and facing blocks, copper weathering and waxing, stems, cocoa, nether wart, carpets. The coverage audit lists the same gaps (section 1.3, "Blocks"), and the research report ranks them fifth among missing features (`popular-mods.md` section 3, rank 5) with high weight under the user's rule of 2026-11-14: "anything that can be made in vanilla java should be possible through this app". This ADR covers those blocks plus the audit's other missing vanilla block behaviours (candles, sea pickles, vines, carpets, snow-like layers, rods, scaffolding). Item inventories, commands and the worldgen order have their own ADRs ([0095](0095-item-inventories.md), [0096](0096-commands-creative-tabs-and-script-and-rules-gaps.md), [0097](0097-vanilla-feature-order-as-a-target-fact.md)); the app, flows and tests are [ADR 0101](0101-vanilla-parity-2-flows-studios-try-it-and-tests.md).

Facts come from the fact table of [`PLAN-vanilla-parity-2.md`](../PLAN-vanilla-parity-2.md) (F1–F16, read 2026-11-14 with `javap` over the Loom-cached merged jars of 26.3 and 26.4-snapshot-7 and the cached Fabric API module jars). The ones that shape the decisions:

- Every vanilla class used here has the same constructor and the same public and protected members on both versions (F1–F13), with three exceptions that the runtime never touches: `SimpleWaterloggedBlock.canPlaceLiquid` takes a `Fluid` on 26.3 and a `FluidState` on 26.4 (F11), `WoodType`'s six-argument constructor takes `SoundType` on 26.3 and `ResourceKey<BlockSoundSet>` on 26.4 (F9), and `WoodType.values()` and `WoodTypeBuilder.register` exist on 26.3 only (F9).
- Beds are plain blocks in 26.x: `AbstractBedBlock` (public constructor), `BedBlock(DyeColor, Properties)`, `StrawBedBlock`, block models `template_bed_head` and `template_bed_foot`, and no bed block entity class (F1). Sleeping, spawn setting and exploding follow the environment attributes `gameplay/bed_rule` and `gameplay/straw_bed_rule`.
- Signs keep block entities: vanilla's `SIGN` and `HANGING_SIGN` block entity types accept extra blocks through Fabric's `FabricBlockEntityType.addValidBlock` (both versions, F8). How the client finds a sign's texture for a wood type that is not one of vanilla's is not known from signatures (open fact S1).
- Vanilla keeps weathering in static maps of vanilla blocks (`WeatheringCopper.NEXT_BY_BLOCK`, `PREVIOUS_BY_BLOCK`; the honeycomb's waxing map), and Fabric's `OxidizableBlocksRegistry` is in `fabric-content-registries-v0`, which the 26.4 Fabric API build does not have (F12). The interface `ChangeOverTimeBlock<WeatheringCopper.WeatherState>` (methods `getNext`, `getChanceModifier`, `getAge`, default `changeOverTime`) is public on both.
- Several vanilla classes take their partners as arguments (`TorchBlock(SimpleParticleType, …)`, `StemBlock(fruit, attached stem, seed, soil tag, fruit support tag, …)`, `FlowerPotBlock(Block potted, …)`, `StandingAndWallBlockItem(standing, wall, Direction, …)`, `HangingSignItem(ceiling, wall, …)`), so they fit project content without copying behaviour (F6, F8, F10, F13). Others are known by behaviour to name vanilla items (the sweet berry bush drops sweet berries, a cake takes vanilla candles); which ones is open fact S4, settled by observation in the spike, never by reading method bodies.

## Decision

- **D1 Twenty new `type` values on `msm:block`.** The pattern of ADR 0067 D1 (one field, one element per block, one Studio): `bed`, `cake`, `berry_bush`, `tall_plant`, `ladder`, `torch`, `lantern`, `chain`, `sign`, `hanging_sign`, `potted_plant`, `candle`, `sea_pickle`, `vine`, `carpet`, `layers`, `rod`, `stem`, `cocoa`, `scaffolding`. With the 17 existing types this makes 37. Each has a driver class in `registry/types/` that extends the vanilla class named in the plan's fact table and delegates events, triggers and light to `BlockBehaviourDriver` (ADR 0067 D4). `scaffolding` is conditional: if the spike (S4) shows that vanilla's scaffolding distance counts only vanilla scaffolding and our driver cannot supply its own count without a Mixin, the type is dropped and recorded as a limit before Wave 1.
- **D2 Per-type definition fields** (mcdoc dispatch on `type`, closed per type, defaults in doc comments):
  - `bed`: `rule?: "bed" | "straw_bed"` (default `bed`: vanilla's bed rule attribute decides sleeping, spawn setting and exploding per dimension; `straw_bed` follows `gameplay/straw_bed_rule`), `colour?: <dye colour>` (default `white`; the `BedBlock` colour, which only vanilla code that asks for a bed colour reads).
  - `cake`: `food?: { nutrition: int @ 1..20, saturation: float @ 0..2 }` (default vanilla's slice, 2 and 0.1), `on_eat?: string` (an event, self and other the player). Seven slices (vanilla's `BITES` property); the comparator reads the slices left, as vanilla.
  - `berry_bush`: `berry: item id` (required; usually the element's own seed item, ADR 0068 D2), `harvest?: { ripe: [min, max], full: [min, max] }` (default the counts the spike measures for sweet berries), `hurts?: boolean` (default `true`: slows and damages entities walking through, as vanilla).
  - `tall_plant`: `bonemeal?: "none" | "drop_copy"` (default `drop_copy`, as tall flowers; `none` as tall grass).
  - `torch`: `particle?: particle id` (an option-less particle type; default `minecraft:flame`; project particle types qualify, [ADR 0080](0080-custom-particle-types.md) D1).
  - `sign`, `hanging_sign`: `wood_type` (required, one of the target's wood type names, ADR 0067 D2: it gives the sounds).
  - `potted_plant`: `plant: block id` (required; a project `sapling`, `berry_bush` or `block` with a cross model, or a vanilla plant that vanilla does not pot; tall plants cannot be potted, as in vanilla).
  - `stem`: `fruit: block id` (required; a project `block` or `horizontal` block), `soil?` and `fruit_soil?` (block tag ids; defaults the tags vanilla's melon stem uses, a target fact).
  - `vine`: `spreads?: boolean` (default `true`).
  - `crop` (ADR 0068) gains `soil?: block tag id` (default farmland, as today), so nether-wart-like crops grow on soul sand.
  - `ladder`, `lantern`, `chain`, `candle`, `sea_pickle`, `carpet`, `layers`, `rod`, `cocoa`, `scaffolding`: no extra fields; they behave as their vanilla class.
- **D3 Two-block elements.** `torch`, `sign`, `hanging_sign` and `stem` register a second block, `<path>_wall` (torch, sign, hanging sign) or `<path>_attached` (stem), with the same properties, no item of its own and a loot preset that drops the element's item. The item is vanilla's `StandingAndWallBlockItem` (torch, sign) or `HangingSignItem`. The generated id is reserved: a project element with it is a validator error (`blocks-items.generated-block-clash`) and a runtime load error that skips the element. Tags, commands and Rules may name the companion. We chose generated companions over two elements because the pair is one thing to the user and vanilla always registers both.
- **D4 Components per new type.** `msm:breakable`, `msm:light_emitter`, `msm:flammable` and the triggers of ADR 0067 D3 are allowed on all twenty types; light defaults follow vanilla (torch 14, lantern 15, candle 3 per lit candle, sea pickle 6 to 15 by count when in water, rod 14) and `msm:light_emitter` overrides them except on `candle` and `sea_pickle`, whose light depends on the state (a validator warning). `msm:shape`, `msm:redstone`, `msm:container`, `msm:machine` and `msm:strippable` are not allowed (`blocks-items.component-not-for-type`). `msm:on_interact` fires after vanilla's own use (a cake slice is eaten, a bush harvested, a candle lit).
- **D5 Behaviour that names vanilla content is our own.** Where the spike finds a vanilla class giving vanilla items or blocks (S4: berry harvest drop and pick-block item, cake candles, cocoa support, nether wart soil), the driver overrides that member with behaviour written from this ADR: the bush drops `berry` with the `harvest` counts, a project cake refuses candles (no candle cakes, limit Q4), cocoa and crops check their tag fields. Nothing is transcribed from vanilla bodies (the plan's clean-room rule).
- **D6 Signs.** A `sign` or `hanging_sign` element makes an unregistered `WoodType` of its own named by the identifier `<namespace>:<path>` that copies the sounds of its `wood_type` (`WoodTypeBuilder.copyOf(...).build(id, setType)`, the same source on both versions; amended after B440) and adds both of its blocks to vanilla's `SIGN` or `HANGING_SIGN` block entity type with `addValidBlock`. Vanilla's sign editing screen, text, dyes, glow ink, waxing and the sign renderer are used unchanged. Lowering writes the sign textures where the client looks for that wood type (S1): block models parented on vanilla's sign templates and the edit-screen pictures `textures/gui/signs/<path>.png` and `textures/gui/hanging_signs/<path>.png` (B440). Lowering cannot copy picture bytes (it sees only the element), so the Block Studio writes the edit-screen picture as a project asset at that id (an undoable asset write, `signGuiTextureId`) whenever the sign's `sign` or `hanging_gui` picture is chosen, and a validator warns when the asset is missing (amended at B448). If the spike finds the client cannot draw a sign of an unregistered wood type on 26.4 without client code, the fallback is the vetoable D6b: the sign borrows the look of its `wood_type` (vanilla's texture) and only its item picture is the project's own; this is decided at B440 and written into the notes before B446 starts.
- **D7 Waterlogging.** A component `msm:waterloggable` (an empty struct) on `block`, `pillar`, `horizontal` and `directional`. The runtime builds `MsmWaterloggedBlock extends MsmBlock implements SimpleWaterloggedBlock` (and the container variant only if the spike shows no conflict with `MsmContainerBlock`; otherwise containers stay unwaterloggable, limit Q8). The new types that vanilla waterlogs (ladder, lantern, chain, signs, candle, sea pickle, scaffolding, rod is not) keep vanilla's own waterlogging, as the families of ADR 0067 do. The runtime never overrides `canPlaceLiquid` (F11). Lowering adds `waterlogged` to the blockstate's variants with the same models.
- **D8 Weathering.** A component `msm:weathering { next?: block id, stage: "unaffected" | "exposed" | "weathered" | "oxidized" }` on `block`, `pillar`, `horizontal`, `directional`, `slab`, `stairs`, `door`, `trapdoor`, `pane` (bars), `chain` and `lantern`, the types vanilla's copper comes in apart from bulbs. Each allowed type has a small weathering subclass (`MsmWeatheringBlock`, `MsmWeatheringSlabBlock`, …) that implements `ChangeOverTimeBlock<WeatherState>` and runs vanilla's own default `changeOverTime` from its random tick, so the chance and the neighbour rule are vanilla's, and project copper next to vanilla copper slows the same way, in both directions (a lower-stage neighbour of either kind stops ageing; measured at B440). Subclasses return 0.75 from `getChanceModifier` at the unaffected stage, as vanilla's copper does. `getNext` returns `next`; the last stage has no `next`. Blocks without the component are never `ChangeOverTimeBlock`s, so vanilla copper is not affected by them. The runtime keeps its own maps (next, previous); vanilla's static maps and Fabric's registry are not used (F12).
- **D9 Waxing and scraping.** A component `msm:waxable { into: block id }` on weathering blocks, and the waxed block names its unwaxed partner implicitly (the reverse map). Through the runtime's existing `UseBlockCallback` (ADR 0067 D4 stripping): `minecraft:honeycomb` waxes (`minecraft:item.honeycomb.wax_on`, the `wax_on` particles, one honeycomb used outside creative); an item whose `minecraft:block_transformer` names `minecraft:axe` unwaxes a waxed block (`item.axe.wax_off`) or scrapes a weathering block one stage back (`item.axe.scrape`), damaging the axe by one; state properties shared by the two blocks are copied. Lightning does not scrape project copper (limit Q6).
- **D10 Lowering** (`@msm/plugin-blocks-items`, one file per type in `lowering/types/`): the definition, blockstates in vanilla's shape per type, block models parented on vanilla's templates for the type (beds, torches and wall torches, lanterns, candles one to four lit and unlit, cakes and slices, stems by age and attached, cocoa by age, vines multipart, carpets, layer heights, rods, scaffolding stable and unstable, potted cross), the item model definitions, the tags the type joins (`#minecraft:beds`, `#minecraft:climbable`, `#minecraft:candles`, `#minecraft:flower_pots`, the four sign tags; every name checked against both targets' vendored registries), the loot presets (bed drops from the head only, tall plants from the lower half, candles by count, sea pickles by count, signs and torches drop the item from both blocks, layers by count, potted plants drop the pot and the plant) and the editor-only textures of each type (`sign` and `hanging_sign` add `sign` and `hanging_gui` texture slots, D6). The model template names are checked against a target fact list (`BlockFacts.modelTemplates`) in the plugin tests.
- **D11 Validators** (`blocks-items.*`, new file `validators-types-2.ts`): `generated-block-clash`, `berry-unknown`, `potted-plant-unknown`, `potted-plant-not-plant` (warning), `stem-fruit-unknown`, `torch-particle-not-simple` (a particle type with options), `weathering-next-unknown`, `weathering-cycle`, `weathering-stage-order` (warning: `next` is not one stage later), `waxable-not-weathering`, `waxable-target-unknown`, `light-fixed-by-state` (warning, D4), and the existing `component-not-for-type` and `type-needs-appearance` learn the new types.
- **D12 Versions.** Shared runtime code except the `WoodTypes` seam (D6) and anything the spike adds. Plugin API 1.17.0 (additive, shared with ADRs 0095–0097): `BlockFacts` gains `bedRules`, `dyeColours`, `stemTags`, `modelTemplates` and `defaultTorchParticle`. Vehicles' plugin API 1.16.0 is taken first; if vehicles land later, the numbers swap at merge.
- **D13 Java eject (26.3 generator).** The generator gains the twenty types, the companions, waterlogging, weathering and waxing (a generated `BlockWaxing` class next to `BlockStripping`); signs follow the D6 outcome.
- **D14 Not in this batch (limits Q1–Q12 in the plan).** Candle cakes on project cakes; a project empty flower pot (a project plant goes into vanilla's pot only, because a pot's content map is keyed by plant); lightning scraping project copper; copper golems, bulbs and copper chests of our own; snow-like accumulation of project layers from weather; bed colours outside the sixteen dyes; signs on family types; hanging signs that attach to project chains in ways vanilla's chain rule does not; glow lichen-like multiface blocks and growing plants (kelp, twisting vines, cave vines, bamboo, sugar cane, cactus, dripleaf) stay for a later batch.

## Consequences

- Format 1 grows additively: twenty `type` values, one crop field, three components. The corpus (prefixes `block-type-2-`, `waterlog-`, `weathering-`), the Codecs, the plugin, the generator and the app move together. A block without these is unchanged.
- The runtime's first generated companion blocks; references and the Studio show them as part of their element.
- Vanilla's own logic runs for weathering chances, sign editing, sleeping, climbing (by tag) and plant growth; the runtime only supplies what vanilla keeps in static maps of vanilla blocks.
- Vanilla pack safety ([ADR 0066](0066-vanilla-pack-safety.md)) needs no new rule: every new block is mod-only.

## Status

Proposed (2026-11-14). Nothing after B440 starts before its notes settle S1 (sign textures), S4 (vanilla content named by vanilla classes) and S5 (weathering neighbours). Defaults the user may veto: the twenty types as `type` values (D1) and `scaffolding` only if the spike allows; bed `rule` and `colour` defaults (D2); berry harvest counts measured from vanilla, bushes hurt by default (D2); generated companions `<path>_wall` and `<path>_attached` (D3); vanilla light levels (D4); no candle cakes (D5); signs with their own wood type and the borrowed-look fallback D6b; `msm:waterloggable` only on the `MsmBlock` types (D7); weathering through vanilla's own `changeOverTime` on the listed types (D8); honeycomb and axes as vanilla, no lightning scraping (D9).
