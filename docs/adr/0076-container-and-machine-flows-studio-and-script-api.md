# ADR 0076: Container and machine flows, Studio sections and Script API 1.2

## Context

[ADR 0074](0074-containers-and-block-entities.md) and [ADR 0075](0075-machines-and-machine-recipes.md) add `msm:container`, `msm:machine` and machine recipes. Beginners need them in the Block Studio and the Creator, power users from scripts, and the library needs templates and examples. `app.asar` is 31.4 of its 32 MB budget (audit L15), and the Block Studio is imported eagerly into the renderer's main chunk, so new UI has to be small and loaded on demand. The plan `docs/PLAN-containers-machines.md` holds the briefs.

## Decision

- **D1 Block Studio: one "Inventory" section.** The Block Studio gains an "Inventory" section, loaded with `React.lazy` from `studios/blocks-items/InventorySection.tsx` (model in `inventory-model.ts`), shown only for the types `block`, `pillar`, `horizontal` and `directional`. A picker "Holds items" chooses None, Storage or Machine; switching is one undo step that removes the other component. Storage fields: Layout ("Chest", "Hopper (5 slots)", "Dispenser (3 by 3)", "No screen (holder)"), Rows (1 to 6), Slots (holder), "Keep contents when broken" (offered only for a 3-row chest), "Hoppers can use it", "Comparators read it", open and close sounds (the existing sound picker), the open and close events. Machine fields: "Recipes it uses" (its own, Smelting, Blasting, Smoking, Campfire cooking), Power ("Fuel", "Redstone signal", "Always"), Speed, Default time (seconds shown, ticks saved), Screen (Furnace, Blast furnace, Smoker), "Hoppers can use it", Comparator ("Contents", "Progress", "Nothing"), Light while working, the start and finish events, and a "Recipes" table (ingredient item or tag picker, count, result item picker, count, time, experience; rows added and removed as one undo step each). The Textures section gains the slots "Front when open" and "Front when working" for the facing types, and the Models section the slots `open` and `lit`. The renderer chunk of the section stays under 60 kB (checked with `tools/check-size` in the brief).
- **D2 Creator flows** (group `blocks`), each a starter with `creator` under the rules of [ADR 0043](0043-creator-guided-flows.md) and the reopen rule: **"Storage crate"** (a `directional` block with `msm:container`, choices: size Small 1 row, Medium 3 rows, Large 6 rows; "Keep contents when broken"; wood or stone look; a crafting recipe; a front and an open front picture) and **"Machine"** (a `horizontal` block with `msm:machine`, choices: power, speed, the vanilla recipe types it also takes, up to three recipes of its own, a crafting recipe, front, front-when-working, side and top pictures). Both create with their untouched defaults and zero problems (the lesson of [ADR 0069](0069-block-family-flows.md)).
- **D3 Templates** (`@msm/plugin-blocks-items`, blocks group): "Storage crate", "Small crate (1 row)", "Item holder" (`none`, 1 slot), "Hopper box", "Dispenser box", "Grinder machine" (own recipes, fuel), "Fast furnace" (smelting, speed 2), "Redstone machine" (`power: redstone`). Eight templates.
- **D4 Examples** (`@msm/plugin-library`): "Loot crate in a structure" (a container with a loot table, placed by a structure template), "Ore crusher" (a machine with three recipes and a hopper chain), "Shulker crate" (keep contents). Each passes the library test on both targets, its vanilla data pack loads on vanilla servers (machine recipes and mod-only loot left out, ADR 0066).
- **D5 Script API 1.2 (additive; the contract keeps `version: 1`).** `World.getContainer(pos)` returns a `Container` for any block entity that is a vanilla `Container` (chests, barrels, hoppers, furnaces and MSM containers and machines) or `undefined`; `Container` has `size`, `get(slot)` (an `ItemRef` copy or `undefined`), `set(slot, item?)`, `count(item)` and `add(item)` (inserts as a hopper would, respecting `canPlaceItem`, and returns what did not fit as an `ItemRef` or `undefined`). Writes mark the block entity changed and update comparators. Events stay definition events (`on_open`, `on_close`, `on_start`, `on_finish`), which can run `run_script`; no new script events. The change follows the usual order: `script-api-v1.json`, the regenerated `api/msm-runtime.d.ts`, the runtime's `ScriptApi`, `ScriptApiContractTest`.
- **D6 AI helper.** The system prompt's block knowledge gains `msm:container`, `msm:machine`, the recipe list and the limits users meet (vanilla screens only, three slots, recipes left out of vanilla packs); summaries name the layout and the machine's recipe count.
- **D7 Testing.** A new fixture `fixtures/sample-machines` (a storage crate, a holder, a hopper box, a keep-contents crate, a fuel machine with its own recipes, a fast furnace on smelting, a redstone machine, functions that say a line on each event) rather than more of `sample-mod`, so the sample mod's goldens and 83 parity tests stay untouched. It is pinned by golden tests for both targets, exported, server-checked and parity-run in CI on 26.3 (content and ejected jars) and 26.4 (content jar), with `SampleMachinesParityTest` (vanilla classes and commands only: `/item`, `/data`, hoppers, comparators, `Player.openMenu`, `containerMenu`, mock players). The runtime adds `MsmContainerGameTest`, `MsmMachineGameTest`, `MsmMachineRecipeGameTest` and `MsmContainerScriptGameTest`. The app adds the e2e `machines-path`. Screens are checked in game (`fixtures/sample-machines/README.md`).
- **D8 Guide.** A new page `docs/guide/containers-and-machines.md` (with a sidebar entry), linked from `blocks-and-items.md` and `creator.md`, saying what the player sees and the limits of the plan that users meet.

## Consequences

- About 8 templates, 2 starters and 3 examples join the library (estimated well under 100 kB in the asar); the briefs that add them check the budget. If `app.asar` passes 31.8 MB, the reserve brief "vendored target data outside the asar" (audit L15) runs before them.
- Script API 1.2 works on vanilla containers too, so scripts gain chest and furnace access as a side effect.
- The sample machines fixture adds one CI server and three parity runs to the `engine-mod` job (about two minutes).

## Status

Accepted (2026-11-14), with the defaults below; the user may still veto: the section name "Inventory" and its labels (D1); the flow names "Storage crate" and "Machine" and their choices (D2); the eight template names (D3); `World.getContainer` and the `Container` type's names (D5); a new fixture rather than more of the sample mod (D7).
