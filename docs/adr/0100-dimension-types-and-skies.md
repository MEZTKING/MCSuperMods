# ADR 0100: Dimension type and sky editing

## Context

[ADR 0051](0051-dimension-creator-flow.md) D1 keeps vanilla dimension types in the Dimension flow; the kind `minecraft:dimension_type` exists for advanced users as a schema form. The research report ranks "dimension type editing and sky effects" sixteenth (a moon-gravity feel, custom skies, fog colours, fixed time) and the coverage audit lists dimension type editing as what remains of backlog B13. All of it is data in 26.x: a `DimensionType` holds height, light, the skybox (`NONE`, `OVERWORLD`, `END`), cardinal lighting, monster settings, timelines, a default clock and an environment attribute map, and the sky, fog, cloud, sun, moon and star looks and many gameplay rules are environment attributes ([ADR 0101](0101-vanilla-parity-2-flows-studios-try-it-and-tests.md#fact-table-f1-to-f36-moved-from-the-plan-at-b485) F31: 51 attribute ids on 26.3, 52 on 26.4, which adds `visual/has_sky_occluder`). A vanilla server refuses the whole data pack when a dimension type names a mod-only particle ([ADR 0066](0066-vanilla-pack-safety.md), the particles batch).

## Decision

- **D1 A Dimension Type Studio** (worldgen plugin's Studio registry) over the existing kind, with sections **Sky** (skybox picture choice; sky, fog, cloud and sunrise colours; cloud height; sun, moon and star angles and star brightness; ambient particles), **Light** (ambient light, sky light, ceiling, cardinal lighting, block light tint), **Time** (a fixed time of day or a clock, through the target's timeline and clock fields: verify at implementation which form 26.3 and 26.4 accept), **Rules** (the `gameplay/*` attributes: bed rule, respawn anchors, piglins turning, monsters burning, fast lava, water evaporating, raids and patrols), **Height** (minimum y, height, logical height) and **Spawning** (monster light test and block light limit). Each attribute field shows only the ids the target's registry lists (`environment_attribute`), so 26.4's extra attribute appears there only. Fields not shown stay in Raw JSON.
- **D2 The Dimension flow** gains the answer "Give it its own sky and rules" (default off, keeping ADR 0051 D1's default): on, it makes a project dimension type copied from the chosen vanilla one with the user's sky colour, fog colour, fixed time choice and "beds explode here" choice, and points the dimension at it. ADR 0051 D1 is superseded only in that the flow may now make a dimension type.
- **D3 Validators** (`worldgen.*`): `dimension-height-multiple` (min y and height multiples of 16), `dimension-height-range` (within the target's bounds, a target fact), `dimension-logical-height` (not above height), `dimension-attribute-unknown` (an attribute id the target does not list), `dimension-attribute-mod-particle` (an info that the file is left out of vanilla packs when it names a project particle, ADR 0066).
- **D4 Preview.** A sky swatch (top colour to horizon fog colour, sun and moon positions at the chosen time) in the Studio and the flow; Try it shows the sky colour (ADR 0101 D5). No 3D sky.
- **D5 Plugin API 1.18.0** (additive): `WorldgenFacts.dimensionHeight?: { minY: number; maxY: number; step: number }` and `WorldgenFacts.environmentAttributes?: readonly string[]` (from the vendored registries; the Biome Studio may use them too).
- **D6 Not in this batch.** Gravity or movement changes per dimension (vanilla has none; Rules can give effects or attributes in a dimension), sky textures and shapes of our own (client code), weather per dimension beyond vanilla's attributes.

## Consequences

- No runtime code and no new kind: the work is app, validators and the flow; vanilla packs carry the result (subject to ADR 0066's fatal-folder rule).
- The Dimension flow keeps its simple default.

## Findings at close (B485)

Recorded 2026-11-21 at the close of vanilla parity 2 batch 2 (B485) from the code on the session branch at 9bbbc65 and the plan's notes: B471 (0eb212e), B473 (f3f892b), B482 (724416f), B483 (9f8e915) and B484 (382e0f3, f16c4d4). The facts are F31 and F35 and the limit Q27 of [ADR 0101](0101-vanilla-parity-2-flows-studios-try-it-and-tests.md)'s fact table and limits. Unreleased; awaiting the user's in-game checks.

- **D1 as built** (B471). `app/src/renderer/src/studios/worldgen/DimensionTypeStudio.tsx` with `dimension-type-sections.tsx` and `dimension-type-model.ts`, lazy (14.9 kB): Sky (with the sky swatch), Light, Time, Rules, Height, Spawning and Advanced. Attribute fields offer only the ids of `WorldgenFacts.environmentAttributes`, so 26.4's `visual/has_sky_occluder` shows there only. **Time:** a fixed time drops `default_clock`, keeps only the `#minecraft:universal` timelines and sets the sun, moon and star angles (noon 0, midnight 180) and the night's sky light; both targets accept that form.
- **D2 as built** (B471). The Dimension flow's answer "Give it its own sky and rules" (`own_sky`, off by default) asks Sky colour, Fog colour, Time of day and Beds in the flow's World step (no new step, Dimension flow only, so the Portal flow and every golden with the answer off are unchanged); on, it adds the dimension type `<id>_type` copied from the chosen vanilla one and points the dimension at it. A copied End type gets `has_ender_dragon_fight: false`.
- **D3 as built** (B471). `worldgen.dimension-height-multiple`, `dimension-height-range`, `dimension-logical-height` and `dimension-attribute-unknown` are errors (a vanilla server refuses the whole pack for an unknown attribute), `dimension-attribute-mod-particle` an info; they read `minecraft:dimension_type` elements and dimension types written inline in a dimension. Templates "Moon dimension type" and "Nether-like dimension type" keep only the attributes the target lists.
- **D4 as built** (B471, B483). `skySwatch` in `dimension-type-model.ts` draws the swatch in the Studio and the flow. **Try it (decision, B483):** the sky is a "Sky" choice in the side panel, not automatic, because the preview area has no dimension of its own; it shows a project dimension type's sky colour and defaults to MSM's own colour (ADR 0085 D7).
- **D5 as built** (B471). Plugin API 1.18.0 `WorldgenFacts.dimensionHeight` `{ minY: -2032, maxY: 2031, step: 16 }` on both targets (the vendored mcdoc ranges) and `environmentAttributes`, the vendored `environment_attribute` registry, namespaced and sorted (51 ids on 26.3, 52 on 26.4). The AI helper reads both through `target_facts` and has a `kind_schema` allowance of 64 list entries for `minecraft:dimension_type` (B484).
- **Tests** (B471, B482, B483). The library's vanilla server check loads a Dimension flow alternative with its own sky (night, exploding beds) on vanilla 26.3 and 26.4 servers; `fixtures/sample-villagers-and-fluids` has the dimension type `glow_moon_sky` (element ids are unique across kinds, so it cannot share the id of its dimension `glow_moon`), and CI pins the Glow Moon level's save line; e2e `fluid-path` reads the flow's sky colour back from the Try it picture.
- **Open follow-ups.** In-game checks of the moon, nether-like and always-night values (sun and star angles, sky light at night); the Biome Studio could offer `environmentAttributes` too; D6's gravity, sky textures and weather per dimension stay out (Q27).

## Status

Accepted with findings at close B485 (2026-11-21; unreleased, awaiting the user's in-game checks), with the defaults below; the user has not yet been shown them and may still veto them. Vetoable defaults as built: a Studio over the existing kind with the sections listed (D1); the flow answer off by default, the type named `<id>_type` (D2); errors and the info as listed, an unknown attribute an error (D3); the Try it sky as a choice, not automatic (D4).
