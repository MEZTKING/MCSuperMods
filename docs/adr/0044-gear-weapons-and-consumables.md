# ADR 0044: Gear, weapons and consumables (more item components, a vanilla component passthrough, more Creator flows)

## Context

[ADR 0042](0042-armour-and-custom-tool-materials.md) added armour because the Gear set flow needed it; the user then said armour was only an example and asked for the other gear and content types a beginner expects. This ADR records what was evaluated on 2026-11-05 against MSM (the MSM mcdoc, the datapack and resourcepack kinds, `msm_runtime`) and against the 26.3 game (vendored registries and mcdoc, `javap` over the Loom-cached 26.3 jar), what is chosen, and what is deferred and why.

What MSM has: item components `msm:food { nutrition, saturation, can_always_eat }`, `msm:tool`, `msm:durability`, `msm:on_use`; block components `msm:breakable`, `msm:light_emitter`, `msm:on_interact`, `msm:on_step`, `msm:redstone`; actions `run_function`, `spawn_particle`, `set_block_state`, `give_item`, `play_sound`, `trigger_event`, `play_animation`, `run_script`; generic schema-form data kinds `minecraft:enchantment`, `damage_type`, `dimension_type`, `chat_type`, `jukebox_song`, `banner_pattern`, `painting_variant`, `trim_material`, `trim_pattern`, `dialog`; `minecraft:recipe` (every vanilla serializer, smithing included); a Custom music disc starter that reskins disc 13 through a `jukebox_playable` select. `MsmItem extends Item` and overrides `use`.

What the 26.3 game offers (verified):

- Data components (127 in the `minecraft:data_component` dispatcher of the vendored mcdoc): among them `consumable { consume_seconds, animation, has_consume_particles, on_consume_effects }` with `consume_effect_type` `apply_effects | clear_all_effects | play_sound | remove_effects | teleport_randomly`; `food` (vanilla's own has `effects`, `eat_seconds`, `using_converts_to`); `use_cooldown`, `use_remainder`; `death_protection { death_effects }`; `blocks_attacks { block_delay_seconds, disable_cooldown_scale, damage_reductions, item_damage, block_sound, disabled_sound, bypassed_by }`; `weapon { item_damage_per_attack, disable_blocking_for_seconds }`; `kinetic_weapon`, `piercing_weapon`, `attack_range`, `minimum_attack_charge`, `attack_animation` (the spear family); `glider`; `jukebox_playable`; `provides_trim_material`, `provides_banner_patterns`; `enchantable`, `repairable`, `damage_resistant`.
- `Item.Properties` helpers: `food(FoodProperties)`, `food(FoodProperties, Consumable)`, `useCooldown(float)`, `usingConvertsTo(Item)`, `spear(ToolMaterial, float ×9)`, `horseArmor(ArmorMaterial)`, `wolfArmor(ArmorMaterial)`, `nautilusArmor(ArmorMaterial)`, `jukeboxPlayable(ResourceKey<JukeboxSong>)`, `trimMaterial(ResourceKey<TrimMaterial>)`, `component(DataComponentType<T>, T)`, `delayedHolderComponent(DataComponentType<Holder<T>>, ResourceKey<T>)`, `enchantable(int)`, `fireResistant()`, `attributes(ItemAttributeModifiers)`.
- Classes: `BowItem(Properties)` and `CrossbowItem(Properties)` over `ProjectileWeaponItem` with `protected shootProjectile(LivingEntity, Projectile, int, float velocity, float inaccuracy, float angle, LivingEntity)`; `MaceItem(Properties)` with `createAttributes()` and `createToolProperties()`; `TridentItem` (its thrown entity renders the vanilla trident model); `ShieldItem(Properties)`; `Consumable(float, ItemUseAnimation, Holder<SoundEvent>, boolean, List<ConsumeEffect>)`, `Consumables.DEFAULT_DRINK`; `ApplyStatusEffectsConsumeEffect(List<MobEffectInstance>, float)`; `DeathProtection(List<ConsumeEffect>)`; `MobEffect` is a code registry (`addAttributeModifier`, `applyEffectTick`), not data driven.
- Vanilla 26.3 ships seven spears (`WOODEN_SPEAR` … `NETHERITE_SPEAR`), the mace, the trident, the shield and the totem of undying; item tags `spears`, `swords`, `trim_materials`, `trimmable_armor`, `enchantable/{bow, crossbow, mace, lunge, melee_weapon, sharp_weapon, weapon, armor, …}`; equipment layers `humanoid`, `humanoid_leggings`, `humanoid_baby`, `wings`, `wolf_body`, `horse_body`, `llama_body`, `happy_ghast_body`, `nautilus_body`, and saddles; `tag/painting_variant` `placeable`; `recipe_type` `smithing` with the `smithing_transform` and `smithing_trim` serializers.

## Decision

**D1. A vanilla component passthrough: `msm:components`.** `ItemComponents` gains `"msm:components"?: struct { [#[id="data_component_type"] string]: minecraft:data_component[[%key]] }`: a map from a vanilla data component id to its vanilla JSON, validated by the vendored mcdoc dispatcher (so every target's own component schemas apply, with version gating). The runtime decodes each entry with `BuiltInRegistries.DATA_COMPONENT_TYPE.get(id).codecOrThrow()` over `RegistryOps` on the built-in registries and applies `props.component(type, value)`; components whose value is a holder in a data-pack registry go through `delayedHolderComponent` for a fixed list (`jukebox_playable`, `provides_trim_material`, `trim`) and are otherwise an error ("component <id> needs a data pack registry; not supported") at load. MSM's own components win on a clash (`msm:food` and `components.food` together is the validator error `blocks-items.component-conflict`). This is the escape hatch that makes gliders, custom use cooldowns, banner-pattern and trim-material providers, music disc items and anything Mojang adds next reachable without a format change; the Creator and the templates use it only where no friendly component exists (D2–D5).

**D2. Friendly consumables: `msm:consumable`.** `struct Consumable { seconds: float @ 0.., animation: ("eat" | "drink" | "none"), effects?: [ConsumeEffect], sound?: #[id="sound_event"] string, particles?: boolean, converts_to?: #[id="item"] string, cooldown_seconds?: float @ 0.. }` with `struct ConsumeEffect { effect: #[id="mob_effect"] string, seconds: float @ 0.., amplifier?: int @ 0..255, chance?: float @ 0..1 }`. With `msm:food` present it lowers to `props.food(FoodProperties, Consumable)`; alone (a potion-like drink, a charm you "use") to `component(CONSUMABLE, …)` plus `use_cooldown` and `use_remainder`. Covers "food with effects" and "potion-like drinks" without touching the vanilla potion system (brewing stays vanilla data). A new action `apply_effect { effect, seconds, amplifier?, target?: "self" | "other" }` joins the action list so events (`msm:on_use`, `msm:on_interact`, entity hits) can give effects too.

**D3. Weapons.** `ToolType` gains `spear` and `mace`: a spear lowers to `props.spear(material, <the vanilla spear constants>)` (the nine floats are read from vanilla's `Items` at implementation and kept as named constants in the runtime; `attack_damage` and `attack_speed` overrides apply to the two they map to), and joins the `minecraft:spears` tag; a mace is `MsmMaceItem extends MaceItem` with the material's durability and enchantment value (its smash attack is vanilla's), tag `enchantable/mace`. New component `msm:ranged_weapon { type: ("bow" | "crossbow"), draw_speed?: float @ 0.1..10 (1 is vanilla), velocity?: float @ 0.1..10, damage_multiplier?: float @ 0..10, inaccuracy?: float @ 0..10 }`: `MsmBowItem extends BowItem` and `MsmCrossbowItem extends CrossbowItem` override `shootProjectile` (velocity, inaccuracy, and `AbstractArrow.setBaseDamage(base × damage_multiplier)`; verify the setter) and `getUseDuration`/the charge time for `draw_speed`; arrows stay vanilla arrows (custom projectile entities are deferred). New component `msm:shield { block_delay_seconds?: float, damage_reduction?: float @ 0..1 (1 blocks all, the default), disable_cooldown_scale?: float, bypassed_by?: #[id(registry="damage_type", tags="required")] string }` lowering to `blocks_attacks` (blocking is component driven since 1.21.5, so a plain `MsmItem` blocks; verified by a GameTest, else `MsmShieldItem extends ShieldItem`) plus `weapon`-side defaults; the model is an ordinary item model (the vanilla shield's banner rendering is not reproduced). `msm:ranged_weapon`, `msm:shield`, `msm:tool` and `msm:armor` are mutually exclusive on one item (`blocks-items.component-conflict`).

**D4. Totem-like items: `msm:death_protection { effects: [ConsumeEffect] }`** lowering to `death_protection` with `apply_effects` (and `clear_all_effects` when `clear_effects: true`); held in either hand like the totem. The item's model is ordinary.

**D5. Horse and wolf armour.** [ADR 0042](0042-armour-and-custom-tool-materials.md) D1 is amended: `ArmorSlot` gains `horse` and `wolf`, lowering to `horseArmor(material)` and `wolfArmor(material)`; the equipment element then needs `layers.horse_body` or `layers.wolf_body`, and the Gear set writes the layer textures for the pieces chosen. (Llama, happy ghast and nautilus body armour and saddles are reachable through D1 plus `equippable`, without a flow.)

**D6. More Creator flows** ([ADR 0043](0043-creator-guided-flows.md) D2 is extended):

- **Gear set** gains pieces `spear`, `mace`, `bow`, `crossbow`, `shield`, `horse_armor`, `wolf_armor`; `upgrade_from` (choice: "craft from scratch", or "upgrade <vanilla material> gear at a smithing table", which adds a smithing template item with a placeholder texture and one `smithing_transform` recipe per piece instead of the crafting recipes; recipe-only, so it ships with the first Gear set); `trim_material` (boolean: the material item also works as an armour trim material: a `minecraft:trim_material` element, `provides_trim_material` through D1 and the `trim_materials` tag; the pieces join `trimmable_armor`).
- **Weapon** (group `gear`): one weapon of a chosen type (sword, spear, mace, bow, crossbow, shield) with material or stats sliders (damage, speed, durability, draw speed, velocity, damage multiplier, block delay) and a tinted silhouette texture.
- **Consumable** (group `food`): kind (`food`, `drink`, `charm`), nutrition and saturation (food), effects list (effect, seconds, amplifier, chance), seconds to consume, cooldown, container returned (drink: glass bottle), always edible; for `charm` the item is not consumed and gives its effects on use with a cooldown (an `msm:on_use` event with `apply_effect`).
- **Totem** (group `gear`): effects granted when the holder would die (regeneration, absorption, fire resistance by default) and the colour.
- **Enchantment** (group `gear`, no runtime: the `minecraft:enchantment` kind): name, what it goes on (choice mapped to `supported_items` tags: swords, bows, crossbows, armour, tools, everything), max level, rarity (weight), one effect template (extra damage, extra knockback, set the target on fire, apply a mob effect on hit, extra durability, mining speed; each a vanilla `effects` component with level-scaled values), optional exclusivity set. Preview: the in-game description and a per-level table.
- **Painting** (group `blocks`, no runtime): title, author, size in blocks (1×1 to 4×4 from the vanilla sizes), the image (a PNG the user picks, scaled to 16 px per block; a tinted placeholder when none): a `minecraft:painting_variant` element, the `placeable` tag entry and the texture. Needs the parameter type `image` (D7).
- **Music disc** (group `blocks`; replaces the disc 13 reskin when the project has the Fabric jar): disc name, colour, the `.ogg` file (imported as an asset), length in seconds, comparator output: a `minecraft:jukebox_song`, a `minecraft:sounds` event, and an `msm:item` with `msm:components.jukebox_playable`; projects that stay vanilla keep the existing starter's disc 13 override (a choice in the flow).

**D7. Parameter type `image`.** `StarterParameter` gains `type: 'image'` (`default: null`, `maxBytes` (1 MB), `maxSize` in pixels; the value is a PNG `data:` URL string or `null`), validated by the host (PNG signature, dimensions); the wizard and the Creator render it with a file picker through `platform.dialogs.pickFiles` and a thumbnail. Flows never read project content; an image is a value like a colour.

**D8. Deferred, with reasons.** *Trident-style throwables:* the thrown entity renders the vanilla trident model, so a custom one needs a projectile entity and a renderer (post-1.0, with custom projectiles for bows). *Custom status effects:* `MobEffect` is a code registry and useful effects need tick behaviour (a scripting hook); vanilla effects through D2 cover the beginner case (post-1.0). *Armour trim patterns:* the `trim_pattern` kind exists, but a pattern needs per-layer textures and a smithing template texture the user must draw; a trim *material* ships (D6) (post-1.0 flow). *Banner patterns:* niche; two hand-drawn 64×64 masks (post-1.0; the kind exists and D1 makes the pattern item possible by hand). *Gliders:* reachable through D1 (`glider` plus `equippable`), no flow. *Custom projectiles and arrows:* post-1.0 with throwables.

**D9. Shipping.** The Gear set's `upgrade_from` ships in **0.7.0** (recipe-only, B183). Everything else here is **0.8.0**: format and plugins (B186), runtime (B187), eject, sample mod and parity (B188), library flows and silhouettes (B189), Creator previews and the image field (B190), tests, guide and release (B191); see the Creator plan (closed with 0.7.0; the 0.8.0 work shipped in the combined 0.7.0, Status below). 0.8.0 follows 0.7.0 and precedes 1.0 only if the user wants it before the Phase 7 close; otherwise B160–B162 run between them (the user decides at the 0.7.0 release).

## Consequences

- Format 1 grows additively again (`msm:components`, `msm:consumable`, `msm:ranged_weapon`, `msm:shield`, `msm:death_protection`, two tool types, two armour slots, the `apply_effect` action); the corpus, Codecs and the eject generator move together; `blocks-items.component-conflict` covers the exclusive sets.
- The runtime gains three item subclasses (`MsmBowItem`, `MsmCrossbowItem`, `MsmMaceItem`) and the passthrough decoder with its delayed-holder list; `fixtures/sample-mod` gains a bow, a drink and a charm; parity grows.
- Plugin API 1.x gains the `image` parameter (additive); the Creator and the wizard render it.
- Seven more flows or flow options for beginners; `tools/check-size` is unaffected (textures are generated, not bundled).
- Follow-ups recorded in the ROADMAP: throwables and custom projectiles, custom status effects with a script hook, trim patterns, banner patterns.

## Status

**Accepted (2026-11-06, shipped in 0.7.0).** The planned 0.8.0 work was folded into the combined 0.7.0 release (main-session decision). `upgrade_from` by B183; format and plugins B186, runtime B187, eject, sample mod and parity B188, library flows B189, Creator previews and the image field B190, tests and guide B191. Originally proposed (2026-11-05).

B187 findings (runtime; B188 mirrors them in the eject generator):

- *Delayed passthrough list (six):* `jukebox_playable`, `provides_trim_material`, `trim` (D1) plus `damage_resistant`, `blocks_attacks` and `damage_type`, which name damage types (a data pack registry). They decode through `Item.Properties.delayedComponent` once data packs are loaded (a late failure logs and leaves the component unset); any other component needing a data pack registry is a load error and the item registers without that entry. Passthrough entries apply first, so MSM's own components win.
- *Spear constants* (from `Items.<clinit>` on 26.3; attack duration, kinetic damage multiplier, delay, dismount max duration and min speed, knockback max duration and min speed, damage max duration and min relative speed): wood 0.65, 0.7, 0.75, 5, 14, 10, 5.1, 15, 4.6; stone 0.75, 0.82, 0.7, 4.5, 13, 9, 5.1, 13.75, 4.6; copper 0.85, 0.82, 0.65, 4, 12, 8.25, 5.1, 12.5, 4.6; iron 0.95, 0.95, 0.6, 2.5, 11, 6.75, 5.1, 11.25, 4.6; gold 0.95, 0.7, 0.7, 3.5, 13, 8.5, 5.1, 13.75, 4.6; diamond 1.05, 1.075, 0.5, 3, 10, 6.5, 5.1, 10, 4.6; netherite 1.15, 1.2, 0.4, 2.5, 9, 5.5, 5.1, 8.75, 4.6. A custom material uses iron's. `attack_speed` sets the attack duration `1 / (attack_speed + 4)` (must be above -4); `attack_damage` replaces the spear's base 0 (the material bonus is still added).
- *Shields:* a plain item with `blocks_attacks` blocks (`Item.use` starts using it), so there is **no `MsmShieldItem`**; shields get 336 durability, enchantable 1, off-hand unswappable and a `break_sound`.
- *Arrows:* `damage_multiplier` calls `AbstractArrow.setBaseDamage(2.0 × factor)`; there is no getter, and **2.0** is the private `ARROW_BASE_DAMAGE` on both versions. `draw_speed` scales the ticks vanilla reads; `velocity` and `inaccuracy` multiply vanilla's values in `shootProjectile`. Bows 384 and crossbows 465 durability, enchantable 1.
- *Maces:* vanilla's tool rule, `weapon(1)` and attributes 5 / -3.4 unless overridden; the material's damage bonus is not added.
- No 26.4 seam was needed (the builder avoids `Consumable.sound()`'s `Optional` on 26.4). Follow-ups: an optional `ArmorDefense.body` for horse and wolf armour (custom materials use `defense.chestplate`), a validator for passthrough holders outside the delayed list.
