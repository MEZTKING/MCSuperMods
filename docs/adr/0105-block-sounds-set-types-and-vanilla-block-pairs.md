# ADR 0105: Own block sounds and set types, and strip, flatten, till, age and burn pairs

## Context

A project block picks one of vanilla's `SoundType` constants (`sound_type`, an enum "to verify at implementation" in `definition.mcdoc`, fact H7); doors, trapdoors, buttons and pressure plates pick one of ten vanilla `BlockSetType` constants (`BlockSetTypes` seam, fact H6; [ADR 0067](0067-block-types-and-states.md) D11 never builds one). Vanilla has a sound set per material, and on 26.4 sound sets are a data registry (`block_sound_set`, a world data folder on 26.4 only), so "my own block sounds" and "my own door sounds" are vanilla things MSM cannot make (coverage audit B2: "own sounds remain").

Vanilla also pairs blocks for tools: an axe strips logs and scrapes copper, a shovel makes a path, a hoe tills soil, honeycomb waxes. MSM has `msm:strippable` and `msm:flammable` for project blocks only ([ADR 0067](0067-block-types-and-states.md)), no flattening or tilling, and nothing for vanilla blocks (coverage audit "Vanilla content modification", fact H8). Fabric's content registries do these on 26.3 (F34 of ADR 0101); they are absent on 26.4, where the runtime already uses a `UseBlockCallback` route for stripping and reflection for flammability.

## Decision

- **D1 Own block sounds.** `msm:block` gains `sounds?: { break, step, place, hit, fall, volume?, pitch? }`, each a vanilla or project sound event; `sound_type` stays and is the default for the events not given. On 26.3 the runtime builds a `SoundType` from them; on 26.4 the lowering writes a `block_sound_set` data entry under the block's id and the block names it, as the spike finds possible (X10: whether a frozen block can name a data entry that loads later; if not, 26.4 uses the nearest `sound_type` and warns, limit N8).
- **D2 Own set types.** `set_type` takes a vanilla name (as now) or an object `{ sounds: { open, close, press?, release? }, can_open_by_hand?: boolean, arrows_press?: boolean, plate_sensitivity?: "everything" | "mobs" }`, built per element on both versions behind the `BlockSetTypes` seam (X11).
- **D3 Flattening and tilling project blocks.** Block components `msm:flattenable { into }` (shovel, as dirt into a path) and `msm:tillable { into, drops? }` (hoe, as dirt into farmland), beside `msm:strippable`; same route as stripping.
- **D4 Pairs for vanilla blocks.** A new addition kind `msm:vanilla_block_rules` (like the additions of [ADR 0060](0060-adding-to-vanilla-content.md)) lists pairs on vanilla blocks: `strip`, `flatten`, `till`, `age` (copper-like `next`), `wax`, and `burn` (`{ burn_odds, spread_odds }`). 26.3 uses Fabric's content registries; 26.4 the existing `UseBlockCallback` and `Flammability` routes, extended (X12); if neither works for a pair on 26.4, the reserve brief B546 adds a version-only Mixin. A pair that overrides a vanilla pair warns, from `TargetFacts.blocks.vanillaPairs`. Fabric mod jar only (limit N9).
- **D5 Target facts.** Plugin API 1.19.0: `BlockFacts.soundTypes` (the vanilla names; the validator reads these instead of the mcdoc enum's comment), `BlockFacts.soundModel` (`"sound_type"` 26.3, `"block_sound_set"` 26.4), `BlockFacts.vanillaPairs` (from B503's dumps), each verified per target.

## Consequences

- Project blocks and doors can sound like themselves; the Sounds section and the Wood set flow offer it.
- Vanilla blocks can be given tool pairs and burning rules; a new addition Studio.
- 26.4's data-driven sounds make the two targets differ in what the lowering writes; the target fact keeps that in `packages/targets`.

## Amendment after the spike (B503, 2026-11-22)

Measured on both versions (evidence in `docs/reference/spikes/b503/`). These win over D1 and D4 where they differ.

- **D1 on 26.4: possible, fixed per world load.** `block_sound_set` is a synchronised world registry, not a reloadable one: the lowering writes `data/<ns>/block_sound_set/<path>.json` (`volume`, `pitch`, `break_sound`, `step_sound`, `place_sound`, `hit_sound`, `fall_sound`) and the block names it by key. A change needs the world opened again (limit N8 reworded), and a missing entry is silent in the game, so the runtime logs a warning for it. `SoundType` does not exist on 26.4.
- **D2.** Own set types work unregistered on both versions behind `BlockSetTypes`; the constructors differ (26.3 takes a name and a `SoundType`, 26.4 a `BlockSoundSet` key).
- **D4 corrected.** Fabric's content registries on 26.3 have no strip, flatten or till registry (only flammability, oxidising and waxing). Strip, flatten, till and wax for vanilla blocks use one `UseBlockCallback` route on both versions, which runs before the item's own transformer; burn uses the existing `Flammability` routes; `age` uses `OxidizableBlocksRegistry` on 26.3, and on 26.4 (where vanilla's maps are immutable and oxidised copper does not random-tick) the reserve brief B546's version-only Mixin, which must also make the vanilla state random-tick. Vanilla's own strip, flatten and till pairs are data (`block_transformer/{axe,shovel,hoe}.json`), so `vanillaPairs` reads them there.

- **Format as frozen (B506).** D1's field is `block_sounds` (a `portal` already has a top-level `sounds`, ADR 0077 D1): `{ break, step, place, hit, fall, volume? 0..10, pitch? 0.25..4 }`. D2's object gains `base` (a vanilla set type, default `wood`, the source of every unset default) and `can_open_by_wind_charge` (default `can_open_by_hand`); all four sounds are optional (a button or plate uses only `press` and `release`). D4's burn rules use `msm:flammable`'s `burn_odds` and `ignite_odds` (0..300) instead of `spread_odds`.

## Findings at close (B523, 2026-11-22)

Recorded at the close of vanilla parity 3 batch 1 (B523) from the code on the session branch at 4ede504 and the plan's notes: B503 (0af2603, the spike), B506 (92ed96f, 447146a), B507 (5149004), B514 (9fe696e), B515 (bc6f27e), the set type follow-up (9958083), the 26.4 sound sets (6d6044f), every vanilla sound type (61eabe2, f152f94), B516 (6f544a0), B517 (9646bad), B518 (a8d50f5), B519 (3b94abc), B520 (c01b166), B521 (3e92e0a), B522 (a517f0c) and the merge findings (3cfb60e). Unreleased; awaiting the user's in-game checks (`fixtures/sample-plants-and-storage/README.md`).

- **Spike answers** (B503, both versions; `docs/reference/spikes/b503/`). **X10:** on 26.3 a `SoundType` built from project sound events works (26.3 has no `block_sound_set` registry); on 26.4 `block_sound_set` is a synchronised world registry (138 entries in the GameTest world, not reloadable), a block registered at start can name an entry by key that loads with the world, and a missing entry is silent. **X11:** own `BlockSetType`s work unregistered on both versions; the constructors differ (26.3 a name and a `SoundType`, 26.4 three flags, the plate sensitivity and a `BlockSoundSet` key). **X12:** Fabric's 26.3 content registries have flammability, oxidising and waxing but no strip, flatten or till registry; one `UseBlockCallback` runs before the item's own transformer on both versions; burning works through the `Flammability` routes (Fabric's registry on 26.3, reflection on 26.4); on 26.4 vanilla's copper maps are immutable and oxidised vanilla copper given a next stage does not random-tick, so `age` there needs the reserve brief B546.
- **D1 as built** (B506, B514, B515 and two follow-ups). The field is `block_sounds { break, step, place, hit, fall, volume? 0..10, pitch? 0.25..4 }`. Seam `registry/OwnSounds`: on 26.3 a `SoundType` from `block_sounds`; on 26.4 the block names the `block_sound_set` key of its own id, and the runtime warns once per missing entry at each world start (`OwnSounds.missingSoundSets()`). The 26.4 lowering writes `data/<ns>/block_sound_set/<path>.json` (`lowering/sounds.ts`, the `{ sound_id }` form, pitch at most 2, volume at least 0.00001), and fills every event, the volume and the pitch `block_sounds` leaves out from the `sound_type`'s own vanilla set (`BlockFacts.soundSetEvents`, 137 sets on 26.4 read from the client jar's data files; `amethyst` read as `amethyst_block`; `stone` by default), so D1's "sound_type is the default for the events not given" holds on both versions (`block-sounds-partial` fires only without the fact). The 26.3 pack ignores `block_sound_set` files. A change on 26.4 shows after the world is opened again (limit N8). Doors, trapdoors, buttons and plates with `block_sounds` need the entry too.
- **Every vanilla sound type** (61eabe2, found by CI). `sound_type` is `(SoundTypeName | string)`: the 40 names stay as suggestions, the runtime resolves any name per version behind `BlockSounds` (26.3 `SoundType` public static fields, 26.4 `BlockSoundSets` keys), an unknown name is a load error that skips the block, and `blocks-items.sound-type-unknown` is an error for a name outside the target's `BlockFacts.soundTypes` (131 names on 26.3, 137 on 26.4; `twisting_vines` and `empty` are 26.3 only, the ice sets and `chiseled_soulshale` 26.4 only). The Block Studio's "Sound type" list offers the 40 and every other name of the target; the 26.3 eject writes any name (`src/sound-types.ts`).
- **D2 as built** (B514, 9958083). `set_type` is a vanilla name or an object `{ base?, sounds?: { open?, close?, press?, release? }, can_open_by_hand?, can_open_by_wind_charge?, arrows_press?, plate_sensitivity? }`; `base` (default `wood`) supplies every unset default and `can_open_by_wind_charge` defaults to `can_open_by_hand`. `BlockSetTypes.of(Identifier, BlockDefinition)` builds an unregistered set type on both versions, also for a vanilla `set_type` when the block has `block_sounds`; callers pass it explicitly (the first `begin`/`end` hook was removed). Stone-based buttons release after 20 ticks; `plate_sensitivity: mobs` ignores items. The Wood set flow's "Door and trapdoor sounds" and "Own door sound" answers write it.
- **D3 as built** (B506, B514, merge findings). `msm:flattenable { into }` and `msm:tillable { into, drops? }` through `BlockExtras`' one `UseBlockCallback` with `msm:strippable`: flattening and tilling need air above and a click not on the bottom face. The Block Studio's Mining section has **Axe strips into**, **Shovel flattens into**, **Hoe tills into** and **Drops once** (3cfb60e; stripping was only under Advanced before).
- **D4 as built** (B506, B514, B515, B517). Kind `msm:vanilla_block_rules` (`vanillaBlockRulesKind`, plugin `msm.blocks-items`, lowered to `msm/<ns>/vanilla_block_rules/<path>.json`, layer `msm`; read by `VanillaBlockRulesParser` from `DefinitionScanner.KINDS`, fixed at start). Strip, flatten, till and wax pairs on vanilla blocks go through the same callback (honeycomb uses vanilla's wax-on event; an axe turns a waxed block back); `burn` rules use `msm:flammable`'s `burn_odds` and `ignite_odds` (0..300) through `Flammability`; log line `registered N vanilla block rule(s) from M file(s)`; unknown `into` or `drops` found after start are only logged (`BlockExtras.lateWarnings()`). `age` works on 26.3 through `OxidizableBlocksRegistry`, and only for blocks that already age as copper does (`WeatheringCopper`); on 26.4 it is skipped with "ageing vanilla blocks is not on this Minecraft version (26.4); the rule is skipped". **The reserve brief B546 was not run in batch 1**; it stays in reserve for after batch 2's Mixin work (decision at this close). The "Vanilla block rules" Studio warns, from `blocks.vanillaPairs`, on a pair whose from-id vanilla already pairs ("Minecraft already turns it into X; this rule replaces that"); an `age` pair on a block that already ages replaces vanilla's next stage. Vanilla packs get `export.needs-jar` per rules element (limit N9). **The eject leaves the kind out** with one `export.not-in-eject` (the generator needs a `JavaProjectInput.vanillaBlockRules` field, planned for B527 with `BlockStripping`, `BlockWaxing`, Fabric's `FlammableBlockRegistry` and `OxidizableBlocksRegistry`). A rules template (`msm_vanilla_block_rules`) and an example are in the library; the sidebar heads the kind "Vanilla block rules".
- **D5 as built** (B507, the 26.4 sound sets). Plugin API 1.19.0: `BlockFacts.soundTypes`, `soundModel` (`sound_type` on 26.3, `block_sound_set` on 26.4; absent counts as `sound_type`), `vanillaPairs { strip, flatten, till, wax, age }` (namespaced block id to block id; 25, 6, 5, 60 and 45 pairs on both targets; strip, flatten and till from vanilla's `block_transformer/{axe,shovel,hoe}.json`, which a pack can change, so the facts are vanilla's defaults) and `soundSetEvents` (26.4 only), checked against the cached client jar by `packages/targets/all/test/block-facts.test.ts`. The AI helper's `target_facts` leaves out `vanillaPairs` and `soundSetEvents` (about 9 kB and over a hundred entries).
- **Tests** (B514, B520). GameTests on both versions; parity cases for the chime stone's and the creaky door's sounds heard by a second player and the loam's flatten and till; `SamplePlantsAndStorageRulesParityTest` (2 tests, content jars only, because the eject leaves the rules out) for mossy cobblestone, mossy stone bricks, mud, moss blocks and burning brown mushroom blocks; e2e `plants-path` exports the 26.4 `block_sound_set`.
- **Open follow-ups.** B546 (`age` on 26.4 by a version-only Mixin that also makes the vanilla state random-tick); the eject of `msm:vanilla_block_rules` (B527); e2e for the Wood set's own door sounds; fluid events cannot yet be changed by a dev overlay (`DevFilesTest.overlayKindsCoverTheScannersKinds` names `fluid` as the one exception).

## Status

Accepted with findings (2026-11-22, close B523; unreleased, awaiting the user's in-game checks). The user has not yet been shown the defaults and may still veto them. Vetoable defaults as built: `sound_type` (any vanilla name of the target) stays the default for missing events, on 26.4 filled from that name's vanilla set; own set types as an object in the same field, built on a `base` of `wood`; own sounds on 26.4 fixed per world load; one addition kind for all vanilla pairs; warnings, not errors, for overriding a vanilla pair; `age` rules skipped with a warning on 26.4 until B546; the rules kind not ejected yet. Proposed at first (2026-11-22) with these defaults: `sound_type` stays the default for missing events; own set types as an object in the same field; one addition kind for all vanilla pairs; warnings, not errors, for overriding a vanilla pair.
