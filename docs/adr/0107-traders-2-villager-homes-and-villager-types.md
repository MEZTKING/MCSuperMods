# ADR 0107: Traders 2, villager homes and villager types

## Context

[ADR 0098](0098-traders-professions-mount-storage-and-shoulder-pets.md) gave any project mob vanilla's merchant screen (`msm:trader`: levels, restock twice a day, `on_trade`) and vanilla villagers project jobs (`msm:villager_profession`, a job site POI through the `PoiTypes` seam). It left out gossip, reputation, demand prices, discounts and workstation restocking for project traders ([ADR 0101](0101-vanilla-parity-2-flows-studios-try-it-and-tests.md) limit Q21), villagers sleeping in project beds (no home POI; ADR 0098 findings) and villager types of our own (fact H12: no registration anywhere). Vanilla has all of these: prices that rise when a player hurts a villager and fall after curing, prices that rise with demand and reset at restock, villagers restocking at their workstation, beds as homes, and seven biome types with their own look.

Vanilla's gossip is brain code that spreads between villagers; MSM's traders are not villagers and have no brain (ADR 0070). What a player sees from gossip is the price change.

## Decision

- **D1 Reputation on project traders.** `msm:trader` gains `reputation?: { hurt?: int, trade?: int, gift_item?: string, gift?: int, decay_per_day?: int, price_step?: int }` (defaults chosen by observation of vanilla's price changes in the spike, X15; verify at implementation): a per-trader, per-player value of our own, saved with the mob, raised by trades and gifts and lowered by hurting it, turned into each offer's special price so the vanilla screen shows the changed price. It does not spread to other mobs (limit N10).
- **D2 Demand.** `msm:trader` gains `demand?: boolean` (default true, as vanilla villagers): vanilla's demand rule on each offer (the price rises after heavy trading and settles at restock), through `MerchantOffer`'s own demand fields (X16).
- **D3 Restocking at a work site.** `msm:trader` gains `work_site?: string` (a block id or tag): when given, the trader walks to the nearest such block within 16 blocks and restocks there (twice a day, as vanilla), instead of restocking in place (X17).
- **D4 Project beds as homes.** Villagers claim and sleep in project beds. If vanilla's home POI matches every block in `#minecraft:beds` (X18), the bed type already joining that tag is enough; else the bed's states are registered as a home POI through the `PoiTypes` seam (26.3 Fabric helper, 26.4 reflection, ADR 0098 D2).
- **D5 Villager types.** A new kind `msm:villager_type` (frozen): `biomes` (biome ids or tags where villagers of this type spawn and are born), editor-only pictures for the villager and zombie villager type layers (lowered to vanilla's resource paths), lang. The runtime registers the type at start and maps its biomes; vanilla's renderers draw it from the resource pack with no client code (X19). No trades per type (limit N11, as vanilla).
- **D6 Target facts.** Plugin API 1.20.0: `EntityFacts.villagerTypes` (vanilla's seven, so a project type's id cannot clash and the Studio lists them).

## Consequences

- Project traders behave like villagers in price; vanilla villagers gain project homes and looks.
- Two new saved values on trader mobs (reputation per player, demand per offer); removing `msm:trader` drops them (as ADR 0098's levels).
- One more frozen registry (villager types; limit N1).

## Amendment after the spike (B524, 2026-11-22)

Measured on both versions (evidence in `docs/reference/spikes/b524/`); these win over D1 to D5 where they differ.

- **D1 reputation: go.** A special price set on a project offer reaches the menu, the offers packet and the client's screen. Cost = clamp(base + demand part + special, 1, stack size). Vanilla's measured numbers are the defaults: a hit -25, a trade +2 (cap 25), a gift +25 (cap 25); daily decay 20 for negative and 2 for trading; special price = -floor(reputation x price multiplier). The store is a persistent Fabric attachment per mob, `Map<UUID, Integer>`. The runtime recomputes special prices per player at every menu open and resets them at close (vanilla resets; the runtime does not today).
- **D2 demand: go.** `updateDemand()` before `resetUses()` at each restock gives vanilla's rule (demand may go negative); price rise = max(0, floor(base x demand x multiplier)); demand is saved and synced.
- **D3 work site: go.** A goal searching 16 blocks, walking to the site and restocking within 2 blocks.
- **D4 changed: joining `#minecraft:beds` is not enough.** A project bed becomes a home only when its head states map to vanilla's `home` POI type in `PoiTypes.TYPE_BY_STATE` (a mutable map, set by reflection through the `PoiTypes` seam on both versions, before any world loads; the holder taken from vanilla's red bed head). A villager then claims it and sleeps in it.
- **D5 villager types: go.** Registered in `BuiltInRegistries.VILLAGER_TYPE`, biomes added to the mutable `VillagerType.BY_BIOME` by reflection (warn once if the field is missing); vanilla draws `<ns>:textures/entity/villager/type/<path>.png` and `zombie_villager/type/<path>.png` with no client code.

## Findings at close (B544, 2026-11-22)

Recorded at the close of vanilla parity 3 batch 2 (B544) from the code on the session branch at a57dbd3 and the plan's notes (the plan is deleted at this close): B524 (a11bfed, the spike; amendment c473792), B526 (a8a416b), B527 (04d9019), B528 (fd1b1ce), B530 (1098db0, 96b1af0), B537b (2bf7321), B538 (054e871), B539 (851ff8e), B540 (074e78e), eject 2c (d51e5c7), B541 (f565cf9, a57dbd3), B542 (d888255) and B543 (66043fb). In the 1.5.3 test build except eject 2c; awaiting the user's in-game checks (`fixtures/sample-mobs-and-commands/README.md`).

- **Spike answers** (B524, observed on 26.3 and 26.4-snapshot-7; evidence and the spike source in `docs/reference/spikes/b524/`). **X15:** a special price set by our code on a project offer shows in the menu, the offers packet, the network codec and the client's merchant screen (the struck-through price). Vanilla's numbers, measured on a villager: a hit adds 25 minor negative gossip (reputation -25), a cure 25 minor positive and 20 major positive (counted five times), a trade 2 trading; special price = -floor(reputation x price multiplier); the cost is clamped to 1 and the stack size. **X16:** `MerchantOffer.updateDemand` then `resetUses` gives vanilla's demand (uses minus what was left, per restock; the price rises by floor(base x demand x multiplier) when positive); demand is in the save and network codecs. **X17:** a goal walking to the nearest work site within 16 blocks and restocking there works (10 blocks in 55 ticks). **X18:** vanilla's home POI does not follow `#minecraft:beds`; a project bed is a home once its head states are in vanilla's state map for `minecraft:home` (a mutable map, by reflection, on both versions; Fabric's helper only makes new types). **X19:** a villager type registers at start on both versions, vanilla's biome map (`VillagerType.BY_BIOME`, mutable, by reflection) gives it to natural and bred villagers and zombie villagers of that biome, it saves by id, and vanilla's renderers draw `<ns>:textures/entity/villager/type/<path>.png` and `zombie_villager/type/<path>.png` with no client code.
- **D1 as built** (B527, B528). `msm:trader.reputation { hurt? 25, trade? 2, gift_item?, gift? 25, decay_per_day? 20, price_step? }`. `registry/mob/TraderReputation` keeps a standing of three parts per player (hits, trades, gifts; value = trades + gifts - hits). Hits come from Fabric's `ServerLivingEntityEvents.AFTER_DAMAGE` (unblocked damage with a player as the source), trades from the merchant's own trade call, gifts from a use with the gift item (refused while the trader is dead, a baby or angry). Each clock day the hit part recovers `decay_per_day` and the trade part fades by 2; the gift part never fades (as a cure's in vanilla). `MobTrader.applyPrices(player)` sets every offer's special price at each menu open and at a level-up, and resets it at close: minus the value divided by `price_step`, or without `price_step` minus the value times the offer's own `reputation_discount`, rounded down. **Changed from the amendment:** the standings are saved by `MobTrader` with the mob's own data (`Reputation`, `ReputationDay`), not in a Fabric attachment; removing `msm:trader` drops them, as the Consequences say and as the levels do. The trade and gift caps (25 each) and the trading decay (2 a day) are constants, not fields; the hit cap is 200 (vanilla's minor negative maximum in the spike).
- **D2 as built.** `demand` (default true): `updateDemand()` before `resetUses()` in `MobTrader.restockIfDue`, so heavily used offers cost more until trade slows.
- **D3 as built.** `work_site` (a block id or `#tag`): `goals/RestockAtWorkSiteGoal` looks within 16 blocks, walks, restocks within 2 blocks and gives up after 1200 ticks; it is added on the first server AI step from `MobTrader`, at the priority after the definition's fighting goals. Without a site in range the offers stay used up. It has no day or night rule (vanilla villagers restock only while working): a follow-up.
- **D4 as built** (amended). `MsmBedBlock` calls `PoiTypes.addHome(Block)`, which on both seams puts the bed's head states into vanilla's `home` POI type by reflection before any world loads; a villager claims the bed and sleeps in it (GameTest in the environment `msm_runtime_gametest:b528_day`). The 26.3 eject mirrors it (B537b).
- **D5 as built** (B527, B528, B530, B538, B539). Kind `msm:villager_type` (plugin `msm.entities`; definition `biomes` of ids or `#tags`; element `textures { villager, zombie_villager, hat }`). **Changed:** it has no language text (vanilla's types have none), so D5's "lang" is dropped. `registry/mob/VillagerTypes` registers in `BuiltInRegistries.VILLAGER_TYPE` and adds to `VillagerType.BY_BIOME` by reflection (one warning if the field is missing), resolving tags at start and after a reload; an id beats a tag, the first project type in scan order keeps a biome, and a project type takes a biome from vanilla's own type. Lowering writes the pictures to vanilla's paths with a `.png.mcmeta` for the hat, and copies the villager picture to the zombie villager path when that one is absent, so a look always dresses zombie villagers too. The **Villager look** Studio (`VillagerTypeStudio`) copies picked pictures with `villagerTypeTexturePaths`; the Creator flow **Villager look** makes one with a drawn robe (art recipe `villager_robe`). Validators `msm.entities.villager-type` and `msm.entities.trader-reputation` (14 villager codes in all, in plain words for Very easy).
- **D6 as built.** `EntityFacts.villagerTypes` holds vanilla's seven on both targets (plugin API 1.20.0).
- **The rest of the product** (ADR 0112 findings): the Trader section's **Remembers how you treat it**, **Prices rise with demand** and **Restocks at**; the Wandering merchant flow's answers and the template `msm_entity_fair_trader`; Try it's merchant mock-up with reputation prices by the floor rule, demand per restock and work sites; the 26.3 eject of traders with levels, restock, reputation, demand, work sites and `on_trade` (eject 2c: shared classes `Trader`, `MobTrader`, `TraderReputation`, `RestockAtWorkSiteGoal`); e2e `villagers-2-path`.
- **Tests.** `MsmTrader2GameTest` and `MsmVillagerTypeGameTest` on both versions (prices after a hit and after trades, demand, restocking at the site, a villager sleeping in a project bed, a villager of a project type in its biome turning into a zombie villager and back); parity cases for the kind merchant's reputation prices, the straw mat as a home and the fen villager type in `SampleMobsAndCommandsParityTest`, on the content jars of both versions and on the 26.3 ejected jar; client GameTest screenshots `msm_villager_plains_<mc>` and `msm_villager_type_<mc>`; `SampleVillagersParityTest` 15 of 15 on the ejected 26.3 jar since eject 2c.
- **Limits.** N10 (reputation is ours: it follows a player's own deeds with that trader and tells no other mob) and N11 (a villager type is a look and a biome list; no trades per type) hold as written. ADR 0101's limit Q21 is closed, and ADR 0098's follow-ups "villagers sleeping in project beds" and "the eject of the four features" are done.
- **Open follow-ups.** A day or night rule for work-site restocking; the villager type picture seen on a zombie villager in a client GameTest (the server tests cover the conversion only); in-game checks of the struck-through price on a real client and of a bed claimed in a real village.

## Status

Accepted with findings (2026-11-22, close B544; in the 1.5.3 test build, awaiting the user's in-game checks). The user has not yet been shown the defaults and may still veto them. Vetoable defaults as built: our own reputation rather than vanilla's gossip (it never spreads); vanilla's measured numbers as defaults (a hit 25, a trade 2, a gift 25, 20 a day recovered) with the caps of 25 and the trading decay of 2 fixed; hits capped at 200; gifts never fading; a gift refused while the trader is dead, a baby or angry; standings saved with the mob rather than in an attachment; demand on by default; restocking at a work site only when one is named, within 16 blocks, with no day or night rule; project beds made homes by reflection into vanilla's `home` POI type on both versions; ids before tags in the biome map, the first project type keeping a biome and a project type taking a biome from vanilla's; a look always dressing zombie villagers too; a villager type without language text; the pictures lowered to vanilla's paths. Proposed at first (2026-11-22) with these defaults: our own reputation rather than vanilla's gossip; demand on by default; restocking at a work site only when one is named; the villager type's pictures lowered to vanilla's paths.
