# ADR 0068: Crops, saplings, trees and leaves

## Context

Coverage audit backlog B12: a project cannot make a crop with growth stages and seeds, a sapling that grows into a tree, or leaves that decay. Trees themselves can already be written as `minecraft:worldgen/feature` elements of type `minecraft:tree` (worldgen plugin, template "Tree (oak-like)"), and [ADR 0060](0060-adding-to-vanilla-content.md) adds placed features to biomes. This ADR builds on the `type` field of [ADR 0067](0067-block-types-and-states.md).

Facts read on 2026-11-14 with `javap` (JDK 25) over the Loom-cached merged jars of 26.3 and 26.4-snapshot-7 and from the vanilla data inside them:

- **`CropBlock(Properties)`** (protected; `extends VegetationBlock implements BonemealableBlock`): static `AGE` (0 to 7) and `MAX_AGE`; overridable `getAgeProperty()`, `getMaxAge()`, `getBaseSeedId()` (vanilla wheat returns `Items.WHEAT_SEEDS`), `getShape` (a static array of eight heights), `mayPlaceOn` (`#minecraft:supports_crops`, which holds `minecraft:farmland`), `getBonemealAgeIncrease`, `createBlockStateDefinition` (adds `AGE`); `isMaxAge` is final and reads `getAge`, which reads `getAgeProperty`. Growth speed reads light and neighbouring farmland (`getGrowthSpeed`, static). Identical on 26.4.
- **Villagers** (`HarvestFarmland`): farmers harvest any `CropBlock` at its maximum age that stands on a `FarmlandBlock`, and replant `BlockItem`s from `#minecraft:villager_plantable_seeds`. Bees grow `#minecraft:bee_growables`.
- **`SaplingBlock(TreeGrower, Properties)`** (protected): `STAGE` 0 to 1, bonemeal, `mayPlaceOn` from `VegetationBlock` (`#minecraft:supports_vegetation`). Identical on 26.4.
- **`TreeGrower` holds `ResourceKey<Feature>`s only** (in 26.x `Feature` is the configured feature, registry `Registries.FEATURE`, folder `worldgen/feature`; the old feature class is now `FeatureType`). `growTree` looks the key up in the server's `registryAccess()` when the sapling grows, so a configured feature from a data pack (the project's, in the mod jar) is found as long as it exists at that moment; a missing key yields an empty `Optional` and the sapling just does not grow. On 26.3 the constructor is `TreeGrower(String name, WeightedList trees, WeightedList megaTrees, WeightedList flowerTrees, ResourceKey shortestTreeType)` and puts itself into a static name map used by its Codec (a duplicate name replaces the old entry); on 26.4 the name, the map and the Codec are gone: `TreeGrower(WeightedList, WeightedList, WeightedList, ResourceKey)`. Two-by-two (mega) trees work for any sapling whose grower has mega trees.
- **`LeavesBlock`** (`SimpleWaterloggedBlock`): `DISTANCE` 1 to 7, `PERSISTENT`, `WATERLOGGED`; decay reads `#minecraft:logs` (distance 1 next to a member). Its subclasses `TintedParticleLeavesBlock(float particleChance, Properties)` (falling leaf particles in the block's tint) and `UntintedParticleLeavesBlock(float, ParticleOptions, AmbientLeavesBlockSoundPlayer, Properties)` (cherry-like). On 26.4 every `AmbientLeavesBlockSoundPlayer` parameter (in `LeavesBlock`, `FallingParticlesLeavesBlock`, `UntintedParticleLeavesBlock`) is an `Optional`.
- **Leaf tint is client code.** `BlockColors.register(List<BlockTintSource>, Block...)` and Fabric `BlockColorRegistry.register(List<BlockTintSource>, Block...)` (fabric-rendering-v1, same signature in the 26.3 and 26.4 builds); `BlockTintSources.foliage()`, `grass()`, `dryFoliage()`, `constant(int)`. Vanilla's `minecraft:block/leaves` model has `tintindex: 0` on every face. The leaf item's tint is data: the item definition's `tints: [{ type: "minecraft:constant", value }]`.
- **Vanilla data shapes (identical on both targets):** wheat's loot is two pools, the produce under `minecraft:match_block` with `state: { age: "7" }` and else the seeds, and extra seeds through `minecraft:apply_bonus` `binomial_with_bonus_count` at the maximum age; leaves' loot uses the predicates `minecraft:tool/can_shear` and `minecraft:tool/can_silk_touch` (present on both targets), `minecraft:table_bonus` chances for the sapling and sticks. The tree feature `oak.json` has `below_trunk_provider` naming `minecraft:soil_beneath_tree` (a `worldgen/block_state_provider` entry), `trunk_provider` and `foliage_provider` with block state properties (`distance: 7`, `persistent: false`). Vendored registries list 10 trunk placer types, 12 foliage placer types and 11 tree decorator types, the same on both targets. Tags present: block `crops`, `supports_crops`, `bee_growables`, `maintains_farmland`, `saplings`, `leaves`, `logs`, `logs_that_burn`; item `villager_plantable_seeds`, `saplings`, `leaves`, `logs`.
- An `msm:block`'s block item always has the block's id today; vanilla seeds (`wheat_seeds` planting `wheat`) do not.

## Decision

- **D1 Types `crop`, `sapling`, `leaves`** on `msm:block` ([ADR 0067](0067-block-types-and-states.md) D1).
- **D2 Block item id.** `item.id?` (an item id; default the block's id) on the block item, in the definition and the element. Used for seeds (`demo:tomatoes` planted from `demo:tomato_seeds`) and for "plant the produce" crops (`demo:carrots` planted from `demo:carrot`, whose food comes from the block item's `msm:components`). The name key is then `item.<ns>.<path>` of the item id (`useItemDescriptionPrefix`), the item model definition goes under the item id, and every registry view counts the item id instead of the block id: the app's `dataRegistryIds`, the library test, the AI helper's summaries and therefore ADR 0066's `modOnlyIdsOf`. One helper, `blockItemId(element)` in `@msm/plugin-blocks-items`, is the single source. A clash with another item is a validator error (`blocks-items.block-item-id-clash`) and a runtime load error.
- **D3 Crops.** Definition fields: `max_age?: int @ 1..15` (default 7), `stage_heights?: [int @ 1..16]` of length `max_age + 1` (default vanilla's ramp, `2 + 2 * stage * 7 / max_age` pixels rounded), `soil?: block tag` (default `#minecraft:supports_crops`), `bonemeal_growth?: { min: int, max: int }` (default vanilla's 2 to 5). Runtime `MsmCropBlock extends CropBlock` with an `IntegerProperty.create("age", 0, max_age)` built through the thread-local pattern, overriding `getAgeProperty`, `getMaxAge`, `createBlockStateDefinition` (without vanilla's `AGE`), `getShape`, `mayPlaceOn` and `getBaseSeedId` (its own block item). Growth, light, bonemeal, trampling, bees and villagers stay vanilla. Editor loot preset `loot: "crop"` with `crop_drops: { produce: item id, produce_count?: int range, seed_bonus?: boolean (default true) }` lowers to wheat's shape (`match_block` on the maximum age); "plant the produce" is `produce` equal to the seed item. Lowering writes the stage blockstate (`age=N` to `<ns>:block/<path>_stage<N>`, parent `minecraft:block/crop` from `textures.stages`, a list of `max_age + 1` textures; fewer textures are repeated, as vanilla potatoes do), the block tags `crops`, `bee_growables` and `maintains_farmland`, and the item tag `villager_plantable_seeds` unless the element says `villager_plantable: false` (default, vetoable). Villagers only farm crops on farmland (a custom `soil` keeps them away; recorded, not fixed).
- **D4 Saplings.** Definition fields: `tree: feature id` (required; a configured feature, folder `worldgen/feature`), `mega_tree?`, `flower_tree?` (the tree grown when flowers are near, as vanilla oak's bee-nest trees; default `tree`), `soil?: block tag` (default `#minecraft:supports_vegetation`). Runtime `MsmSaplingBlock extends SaplingBlock` with a `TreeGrower` made at registration from `ResourceKey`s (seam `registry/TreeGrowers`: 26.3 passes the name `<ns>:<path>`, so no vanilla grower is replaced in the name map; 26.4 has no name). Timing is safe: keys resolve when the sapling grows. A key missing from the server's registry is reported once per sapling on `SERVER_STARTED` as a warning (`[msm_runtime] sapling <id>: tree feature <key> is not in any loaded data pack`); the sapling then does not grow, as vanilla would. Lowering writes a `cross` model from `textures.sapling`, the item model (`item/generated`), the tags `saplings` (block and item), and the potted plant is not made (ADR 0067 D11).
- **D5 Trees** stay `minecraft:worldgen/feature` elements of type `minecraft:tree` (no new kind). The worldgen plugin gains templates "Tree for a sapling" (a project log and leaves through `<projectNamespace>:root`-derived ids) and the app a Tree section in the feature form (trunk placer, foliage placer and decorator pickers from the target's vendored registries, the trunk and foliage blocks, the leaves' `distance` and `persistent` state filled in). Vanilla trunk and foliage placer types are the only shapes: a new placer type is code in a code registry (limit, D9). A project tree that should grow in the world uses a placed feature and an `msm:biome_addition` ([ADR 0060](0060-adding-to-vanilla-content.md)); the wizard offers it ([ADR 0069](0069-block-family-flows.md)).
- **D6 Leaves.** Definition fields: `tint?: ("foliage" | "grass" | "dry_foliage" | int colour)` (absent: no tint, the texture's own colours), `particle_chance?: float @ 0..1` (default vanilla's 0.01), `falling_particle?: particle id` (only without `tint`; absent: none). Runtime `MsmLeavesBlock` extends `TintedParticleLeavesBlock` with a tint and `UntintedParticleLeavesBlock` without (seam `registry/Leaves` for the 26.4 `Optional` constructors), with vanilla leaf properties (`noOcclusion`, never suffocating or view-blocking, `isValidSpawn` for ocelots and parrots only, `pushReaction` destroy, ignited by lava). **The tint is the runtime's first client block hook:** `MsmRuntimeClient` registers every tinted leaves block with `BlockColorRegistry.register(List.of(source), block)` (`BlockTintSources.foliage()`, `grass()`, `dryFoliage()` or `constant(rgb)`); this cannot be tested in CI (audit L16) and is an in-game check. Lowering writes the model parented on `minecraft:block/leaves` (tint index 0) from `textures.all`, the item definition with a constant tint (vanilla's default foliage colour for `foliage`, the given colour for a number; default, vetoable), the tags `leaves` (block and item) and `mineable/hoe`. Editor loot preset `loot: "leaves"` with `leaves_drops: { sapling?: item id, sticks?: boolean (default true), extra?: { item, chances? } }` lowers to vanilla's oak leaves shape (shears or silk touch drop the leaves; otherwise `table_bonus` chances 0.05 to 0.1 for the sapling, sticks, and the extra item as vanilla's apple at 0.005 to 0.025). Decay works only when the tree's trunk block is in `#minecraft:logs`: validator `blocks-items.leaves-will-decay` warns when a sapling's project tree names project leaves and a project trunk block that no project tag puts in `minecraft:logs`.
- **D7 Validators** (codes `blocks-items.*`): `crop-stage-heights-length`, `crop-without-produce` (loot preset `crop` without `produce`), `sapling-tree-unknown` (neither a project `worldgen/feature` nor a vanilla configured feature id from the target), `sapling-tree-not-tree` (warning: a project feature of another type; any feature works, but saplings expect trees), `leaves-will-decay`, `block-item-id-clash`, `particle-on-tinted-leaves`.
- **D8 Versions and eject.** Shared runtime code apart from two seams, `TreeGrowers` and `Leaves` (both with GameTest seam checks); `BlockColorRegistry` and `BlockTintSources` are the same on both targets. Target facts gain nothing beyond ADR 0067 D9 (the tint names are MSM names). The 26.3 Java generator emits the crop, sapling and leaves classes, the `TreeGrower` with the name `<ns>:<path>`, the `SERVER_STARTED` check and a client entrypoint registering leaf tints (`ClientModInitializer` and the `client` entrypoint in the generated `fabric.mod.json`).
- **D9 Limits recorded.** New trunk or foliage placer shapes (code registries; vanilla placers only). Tint by any rule other than the four vanilla sources and a constant (client code per rule). A tree grown from data cannot be checked for existence before a world loads (only the start-up warning of D4). Villagers farm only crops on farmland. Stems with an attached fruit (melon and pumpkin stems), berry bushes, tall double plants, cocoa and nether wart need their own classes; not in this batch. Flower pots for saplings (a `FlowerPotBlock` per plant). Leaves' ambient sounds (`AmbientLeavesBlockSoundPlayer`) stay absent.

## Consequences

- Crops, saplings and leaves are ordinary `msm:block` elements; a tree is an ordinary worldgen element, so a tree can be tested in the worldgen Studio without a sapling.
- `item.id` is the first block item that does not share the block's id; four places that assumed equality move to `blockItemId` in the same batch (registry view, library test, AI summaries, eject).
- Vanilla pack safety ([ADR 0066](0066-vanilla-pack-safety.md)): a tree feature naming project logs and leaves is left out of vanilla data packs, and so is the placed feature that names it (biome additions live in the `msm` layer and never reach a vanilla pack); the seeds item is mod-only through `blockItemId`. No new rule.
- The runtime's client entrypoint grows from renderers to renderers plus block tints.

## Findings

Recorded at close (2026-11-14) from B258–B281:

- **Leaf decay tag.** Vanilla leaves look for `#minecraft:prevents_nearby_leaf_decay`, not `#minecraft:logs` directly; on both targets that tag contains `#minecraft:logs`, so a trunk in `minecraft:logs` still keeps leaves alive and `blocks-items.leaves-will-decay` (D6, D7) stays right.
- **Pistons.** Crops, saplings and leaves use vanilla's push reaction for plants: a piston pops them (they break and drop) instead of moving them.
- **Villagers on 26.4.** `HarvestFarmland` behaves the same on 26.4-snapshot-7 (fact F16 of the plan, verified in B271): farmers harvest any `CropBlock` at its maximum age on farmland and replant seeds from `#minecraft:villager_plantable_seeds`.
- **No `random_patch` in 26.x.** The feature type is gone, so wild crop patches (ADR 0069 D1) are a `minecraft:simple_block` feature of the crop at its maximum age with a vanilla-shaped placed feature (count, rarity, height map, `block_predicate_filter`) and a project soil tag holding farmland and grass.
- **Seeds names.** The seeds item takes the block's display name (`item.id` has no name of its own; the crop block is named after its seeds). Separate block and item names are a follow-up of the format.
- **Leaves classes.** Three runtime classes: tinted (`TintedParticleLeavesBlock`), untinted with a `falling_particle` (`UntintedParticleLeavesBlock`) and plain; seam `registry/Leaves` for 26.4's `Optional` ambient sound player. Constant tints are registered with full alpha (`0xFF` added to the RGB value). The leaves item always has a constant tint for a tinted block; there is no field to turn it off yet.
- **Saplings.** Seam `registry/TreeGrowers` (26.3: the grower is named after the sapling id); `SaplingCheck` warns once per missing tree feature at server start (D4).
- **Defensive runtime rules.** A `bonemeal_growth` with `min` above `max` is a validator error and the runtime swaps the bounds; `stage_heights` of the wrong length is a validator warning and the runtime falls back to vanilla's ramp. Crop stage models spread over the ages by `floor(age * k / ages)`; the crop's item falls back to the last stage texture.
- **Eject differences** (26.3 generator, B276): a `falling_particle` with options stops start-up instead of being dropped with an error; a wrong-length `stage_heights` and a particle on tinted leaves are silent. The client entrypoint registers leaf tints. The generated project was started on a real 26.3 Fabric server without the runtime.
- GameTests grew to 239 per variant (B271); the leaf tint itself is an in-game check (audit L16).

## Status

Accepted (2026-11-14). Defaults the user may veto: "Villagers plant it" on by default (`villager_plantable`, D3); the leaves item tint (vanilla's default foliage colour for `foliage`, D6); crop `max_age` 7 and vanilla's stage heights and bone meal range.
