# ADR 0111: Command arguments in Rules, more argument types, the R10 triggers, dialogs, game rules, statistics and tab order

## Context

[ADR 0096](0096-commands-creative-tabs-and-script-and-rules-gaps.md) gave projects their own commands (`msm:command`: twelve argument types passed to a function as macro values or to an event) and creative tabs (`as_listed` or `by_name`). Its findings and the coverage audit leave open (fact H15 of [ADR 0112's fact table](0112-vanilla-parity-3-flows-studios-eject-try-it-and-tests.md#fact-table-h1-to-h16-moved-from-the-plan-at-b544)):

- Rules cannot read a command's arguments (a Rules value for them "needs an ADR");
- vanilla has 62 command argument types ([ADR 0101](0101-vanilla-parity-2-flows-studios-try-it-and-tests.md) F36) and MSM offers twelve;
- [ADR 0082](0082-rules-no-code-behaviour.md) limit R10: no triggers for crafting, picking up, eating, sleeping or advancements (server events, not client work);
- a data pack dialog can be opened only by a command in a function;
- game rules and statistics of a mod's own (vanilla has 59 game rules and a `custom_stat` registry; both are registries a mod adds to at start);
- a project tab cannot list its items in a hand-chosen order.

## Decision

- **D1 Command arguments as Rules values.** The Rules value "What the player typed for <argument>" (`command_argument`, slot `name`, typed by the argument's type) is offered on rules whose trigger is "A player types the command"; the compiler reads it from the event context, where the runtime puts each argument under `args.<name>` (as the Script API's `command` event already does). Only the types of D2 that have a Rules value type (number, text, player, entity, position, block, item, dimension, effect) are readable (limit N20).
- **D2 More argument types.** The argument type list grows by those B525 finds working on both versions and reaching the client's command tree (X30): candidates dimension, time, colour, rotation, angle, UUID, objective, score holder, item predicate, block predicate and resources of the effect, enchantment, biome and structure registries. The list lives in `TargetFacts.commands.argumentTypes` (plugin API 1.20.0).
- **D3 The R10 triggers.** Script events `item.crafted` (player, item, count), `item.picked_up` (player, item, count), `player.ate` (player, item), `player.slept` and `player.woke` (player, bed position), `player.advancement` (player, advancement id), and the matching Rules triggers. Fabric events where they exist; otherwise head or return injections under DESIGN section 10's Mixin policy, named by the spike (X33), each with a justification comment and a GameTest on the real path (crafting through the menu, picking up from the ground, eating to the end, a night's sleep, an advancement granted by its own trigger). Not ejected (limit N23).
- **D4 Dialogs.** Event action `open_dialog { dialog }` (a vanilla or project dialog id, for `self` or `other`) and the Rules step "Open a dialog"; Script API `Player.openDialog(id)` (X34).
- **D5 Game rules.** Kind `msm:game_rule` (frozen): `kind` (`boolean` or `integer`, vanilla's two; limit N21), `default`, `category` (vanilla's categories), `min` and `max` for integers, lang for its name and description. Registered at start (X31), set with `/gamerule`, saved per world. Rules condition "The game rule is", step "Set a game rule"; Script API `World.gameRule(id)` and `World.setGameRule(id, value)`.
- **D6 Statistics.** Kind `msm:stat` (frozen): `format` (`default`, `distance` or `time`; limit N22), lang. Registered at start in `custom_stat` (X32); its scoreboard criterion `minecraft.custom:<ns>.<path>` is offered in completions. Rules step "Add to a statistic", condition "The statistic is at least"; Script API `Player.stat(id)` and `Player.addStat(id, amount)`.
- **D7 Tab order by hand.** `msm:creative_tab`'s `order` gains `by_hand` with an `items` list (any item ids, vanilla or project); items of the tab not in the list follow in registration order.
- **D8 Versions.** Script API 1.7 (the events of D3, D4's `openDialog`, D5's and D6's members; labelled with the runtime release at the close). Plugin API 1.20.0 (argument types, `gameRuleKinds`, `statFormats` as target facts).

## Consequences

- Commands become usable from Rules end to end; the When picker gains six triggers.
- Up to five more Mixins (D3), each with its own GameTest; none ejected.
- Two more frozen registries (game rules, statistics; limit N1).

## Amendment after the spike (B525, 2026-11-22)

Measured on both versions (evidence in `docs/reference/spikes/b525/`).

- **Argument types:** 32 types work on both versions and reach the client's command tree, rebuilt on `/reload`: dimension, time, team colour, hex colour, rotation, angle, UUID, objective, score holder(s), item and block predicates, effect, enchantment, biome and entity type (`ResourceArgument` over a registry the client receives), biome or tag, structure and structure or tag (key types), particle, game mode, text component, int range, identifier, team, slot, NBT compound, message, dialog and loot table (`ResourceOrIdArgument`), advancement and recipe (key types). A `ResourceArgument` over a registry the client does not receive (structures) disconnects every client, so such registries are key-only (`CommandFacts.argumentTypes` marks them).
- **Own game rules: go, no Mixin.** Fabric's `GameRuleBuilder` (boolean and integer, with a range and a category), saved with the world, `/gamerule <ns>:<path>` (the namespace is required), Fabric's change callback; lang keys `gamerule.<ns>.<path>` and `.description`.
- **Statistics: go.** Registered in `custom_stat` with the registered `Identifier` instance kept (a new instance throws), criterion `minecraft.custom:<ns>.<path>`, formats default, distance and time, saved per player, lang key `stat.<ns>.<path>`.
- **Events: sleeping and waking by Fabric's `EntitySleepEvents`; crafting, picking up, eating and advancements need Mixins**, each with a justification comment and a GameTest on the real path, all on targets that exist on both versions (no `MixinVersions` entry): head of `ItemStack.onCraftedBy(Player, int)` (once per craft, covers the 2 by 2 grid, the table and furnace results); head and return of `ItemEntity.playerTouch(Player)` (taken = count before minus after, so partial pickups count); head of `Consumable.onConsume(Level, LivingEntity, ItemStack)` (once at the end, drinks too); head and return of `PlayerAdvancements.award` with the head of `AdvancementRewards.grant(ServerPlayer)` (once per completed advancement). A vanilla data route (advancements with a reward function) also counts these without Java.
- **Dialogs: go, no Mixin.** `ServerPlayer.openDialog(Holder<Dialog>)` and `/dialog show` open a project dialog on the client.

## Findings at close (B544, 2026-11-22)

Recorded at the close of vanilla parity 3 batch 2 (B544) from the code on the session branch at a57dbd3 and the plan's notes: B525 (f9d3e39, the spike; amendment 233f397), B526 (a8a416b), B527 (04d9019), B533 (c5daf64, d069932), B534 (7d5bdb3, 8369a3f), B535 (d7f2fdb), the `open_dialog` action (dd7e594, dbc4cd7), B537 (7a70225), B538 (054e871), B539 (851ff8e), B540 (074e78e), B541 (f565cf9, a57dbd3), B542 (d888255) and B543 (66043fb). In the 1.5.3 test build; awaiting the user's in-game checks (`fixtures/sample-mobs-and-commands/README.md`).

- **Spike answers** (B525, both versions; `docs/reference/spikes/b525/`). **X30:** 32 more argument types work through Brigadier with the build context on both versions and reach the client's command tree, rebuilt on `/reload`; a `ResourceArgument` over a registry clients do not receive (structures) disconnects every client, so such registries take a key type. **X31:** own game rules through Fabric's `GameRuleBuilder` (boolean and integer, a range, a category), saved with the world, set by `/gamerule <ns>:<path>` (the namespace is required), with Fabric's change callback; no Mixin. **X32:** a `custom_stat` entry at start (the registered `Identifier` instance must be kept: a new instance throws), the criterion `minecraft.custom:<ns>.<path>`, the formats default, distance and time, saved per player, lang key `stat.<ns>.<path>`. **X33:** sleeping and waking by Fabric's `EntitySleepEvents`; crafting, picking up, eating and advancements have no Fabric event and need Mixins. **X34:** `ServerPlayer.openDialog(Holder<Dialog>)` opens a data pack dialog on the client; no Mixin.
- **D1 as built** (B533, B534). The runtime puts each argument under `args.<name>` on the command's own `run_script` event (`ActionEvent.args`, `CommandEvents.withArgs`). The Rules value `command_argument` ("What the player typed") is offered only on "A player types the command". Readable types (`READABLE_ARGUMENT_TYPES`): integer and number; position and block position by axis; word, text, player, entity, item, block, dimension and effect. Not readable (limit N20): yes or no, several players, time and the other newer types, which still reach functions as macro values and scripts as `args`.
- **D2 as built** (B527, B533, B535). 44 argument types: the twelve of ADR 0096 and the amendment's 32 (`text` and `message` are the rest-of-line types and come last; vanilla's text component is `text_component`). `TargetFacts.commands.argumentTypes` lists them with `keyOnly` on structure, structure or tag, advancement and recipe; the scripting validator reads the facts (`commands.unknown-argument-type`). Each type's macro and script value is fixed in `commands/CommandArguments` (a dimension, effect, enchantment, biome, structure, mob kind, particle, advancement, recipe, id, dialog or loot table as its id; a time in ticks; a hex colour as `#RRGGBB`; a rotation as `yaw pitch`). `angle` (both versions) and `effect` (26.4) have no node in the vanilla command tree, so the facts test allows them by name. **Found in the game:** the hex colour is typed without the `#` (`ff8800`), though it arrives as `#FF8800`; the Command Studio's label still shows an example with `#` (a follow-up; the guide says it).
- **D3 as built** (B533). Events `item.crafted` and `item.picked_up` `{ player, item, count }`, `player.ate` `{ player, item }`, `player.slept` and `player.woke` `{ player, pos }`, `player.advancement` `{ player, advancement }`. Sleeping and waking come from `scripting/MoreEvents` over `EntitySleepEvents`. Five read-only Mixins in the shared config (targets exist on both versions, so no `MixinVersions` entry), each with its justification comment and a GameTest on the real path: `CraftedMixin` (head of `ItemStack.onCraftedBy`), `ItemPickupMixin` (head and return of `ItemEntity.playerTouch`; taken = count before minus after), `ConsumeMixin` (head of `Consumable.onConsume`), `AdvancementMixin` (head and return of `PlayerAdvancements.award`) with `AdvancementRewardsMixin` (head of `AdvancementRewards.grant`). The runtime now has seven shared Mixins and one 26.4-only. Left out on purpose: crafters and dispensers do not fire `item.crafted`; recipe advancements do not fire `player.advancement`. Six Rules triggers match them (`player_crafted`, `player_picked_up`, `player_ate`, `player_slept`, `player_woke`, `player_advancement`), with an optional item or advancement subject.
- **D3 and the eject** (limit N23). Scripts are not ejected at all (`export.scripts-not-ejected`), and rules on the six triggers compile to script, so they are not ejected either. **Not as N23 says:** the eject's per-event warning `export.not-in-eject` still names only the two Mixin events of ADR 0096 (`block.place`, `world.explosion`; `MIXIN_EVENTS` in `packages/exporters/src/java-project/index.ts`), not the four new ones. The user still gets the script warning; naming the events is a small follow-up.
- **D4 as built** (dd7e594). Event action `open_dialog { dialog, target? }` (`Action.OpenDialog`, `EventRunner.openDialog`; `self` or `other` as `apply_effect`; only a `ServerPlayer` gets it), added after B533 because it needed the action schema and corpus. The Rules step "Open a dialog" compiles to the action when the trigger has an action target and to script (`Player.openDialog`) otherwise. The 26.3 eject writes it.
- **D5 as built** (B527, B533, B535). Kind `msm:game_rule` (plugin `msm.scripting`): `kind` (`boolean` or `integer`), `default`, `min` and `max` for integers, `category` (vanilla's seven); lang keys `gamerule.<ns>.<path>` and `.description`. `registry/MsmGameRules` registers through Fabric's `GameRuleBuilder`. **Mismatch to settle:** a boolean rule with `min` or `max` is refused by the runtime's parser and by the eject, while the app's validator only warns. `TargetFacts.gameRules` (kinds, categories, vanilla's 59 names) is a grouped fact rather than D8's `gameRuleKinds` list.
- **D6 as built.** Kind `msm:stat` (plugin `msm.scripting`). **Changed from D6:** the field is `formatter` (`default`, `distance`, `time`), because `format` is the definition's version field. `registry/MsmStats` registers in `custom_stat` and keeps the instance; lang key `stat.<ns>.<path>` (a `/` in the path written as `.`; not checked in the game for such a path). `TargetFacts.stats` (formats, the criterion prefix `minecraft.custom:`, vanilla's 78 custom statistics). Vanilla's `StatFormatter` also has a divide-by-ten format, left out (limit N22).
- **D7 as built.** `order: by_hand` with `items`; `MsmCreativeTabs.handOrder` puts the listed items first and the tab's other items after, in registration order. `items` under another order, or `by_hand` without `items`, is a warning (validator `msm.blocks-items.creative-tab-order`, 4 codes).
- **D8 as built.** Script API 1.7: `World.gameRule(id)` (undefined for an unknown rule) and `setGameRule(id, value)`, `Player.stat(id)`, `addStat(id, amount)` (returns the new value, never below 0) and `openDialog(id)` (false for an unknown dialog), `ActionEvent.args` and the six events; `setGameRule`, `stat` and `addStat` throw for an unknown id. The members say "Since runtime 1.5.3" (decided at the 1.5.3 test build, a4b807f). Plugin API 1.20.0.
- **Rules catalogue** (B534): 62 triggers, 47 steps (`open_dialog`, `add_to_stat`, `set_game_rule`), 21 conditions (`game_rule`, `stat_at_least`), 14 values (`command_argument`), 7 places. A Minecraft game rule's kind is not known in the editor, so its value picker offers both forms.
- **Studios and flows** (ADR 0112 findings): the Command Studio's 44 types in plain words, the **Game rule** and **Statistic** Studios, the Creative tab Studio's **In your own order**, Rule book pickers for the six new slot types, the Game rule flow and the Custom command and Creative tab answers, five scripting templates.
- **Tests.** `MsmCommand2GameTest` (6), `MsmGameRuleStatGameTest` (4) and `MsmScriptApi17GameTest` (11) on both versions; the GameTest mod logs `registered 4 game rule(s)` and `registered 4 statistic(s)`; parity cases for `/signal`'s argument types and dialog (with the unknown-dimension refusal), the game rules bounded by `/gamerule`, the statistics as scoreboard criteria and the hand-ordered tab, on the content jars of both versions and the 26.3 ejected jar, plus five script parity tests on the content jars. **Trap (26.4):** a GameTest that skips the night fast-forwards the server and evicts the 1024-line script log; the sleep test leaves the bed with `players_sleeping_percentage` 101.
- **Eject fix at the close** (a57dbd3). The 26.3 eject now reads every given argument before any command runs, as the runtime does, so an unknown dimension is refused when the command runs, as vanilla's `execute in` refuses it.
- **Limits.** N20, N21 (game rules are true or false, or a whole number) and N22 hold; N23 as above. ADR 0096's follow-up "Rules reading command arguments" and ADR 0082's limit R10 are closed.
- **Open follow-ups.** The Command Studio's hex colour label; `MIXIN_EVENTS` naming the four new events; one rule for a boolean game rule with `min` or `max`; the `stat.<ns>.<path>` key for a path with `/`; "The command does nothing" showing on a command whose rule book has errors; a step after an If reading as if it were in the otherwise branch (sentence wording); no Script API 1.6 line in the AI helper's prompt.

## Status

Accepted with findings (2026-11-22, close B544; in the 1.5.3 test build, awaiting the user's in-game checks). The user has not yet been shown the defaults and may still veto them. Vetoable defaults as built: arguments readable only on the command's own rules and only for the readable types; the 44 argument types, four of them key-only; five read-only Mixins where Fabric has no event; crafters and dispensers not firing `item.crafted` and recipe advancements not firing `player.advancement`; game rules of vanilla's two kinds, typed with their namespace in `/gamerule`; the statistic's field named `formatter`, with vanilla's divide-by-ten format left out; `by_hand` order with unlisted items after; `gameRule` reading undefined for an unknown rule while the other new members throw; "Open a dialog" as a plain action where the trigger has a target; Script API 1.7 labelled "Since runtime 1.5.3". Proposed at first (2026-11-22) with these defaults: arguments readable only on the command's own rules; the argument types the spike confirms; Mixins where Fabric has no event; game rules of vanilla's two kinds only; `by_hand` order with unlisted items after.
