# ADR 0098: Trader mobs, villager professions and job sites, mount storage and shoulder pets

## Context

The research report ranks trader mobs seventh among missing features ("a merchant menu on custom mobs using `villager_trade` and `trade_set`, custom professions and job-site POI types"; wandering merchants, tavern keepers, bounty rewards) and mount inventories and shoulder pets fifteenth (pack mules, pocket hamsters, parrot-like riders). [ADR 0060](0060-adding-to-vanilla-content.md) D5 made trades data (`minecraft:villager_trade`, `minecraft:trade_set` and their tags); [ADR 0071](0071-tameable-breedable-rideable-mobs-variants-and-boss-bars.md) D10 left out mount inventories; [ADR 0077](0077-custom-portal-blocks.md) found that POI types cannot be registered the same way on both versions.

Facts ([ADR 0101](0101-vanilla-parity-2-flows-studios-try-it-and-tests.md#fact-table-f1-to-f36-moved-from-the-plan-at-b485) F20–F26):

- `Merchant` is a public interface (offers, trading player, XP, `openTradingScreen` as a default method), `MerchantMenu(int, Inventory, Merchant)` and `MerchantOffer` (with `CODEC` and `STREAM_CODEC`) are public; `TradeSet.calculateNumberOfTrades(LootContext)` and `VillagerTrade.getOffer(LootContext)` are public, so a project mob can draw offers from data trade sets with vanilla's own rules. Which loot context parameters `getOffer` needs is open (S11). All identical on both versions.
- `VillagerProfession` is a record with a public constructor (name, held and acquirable job site predicates, requested items, secondary POI blocks, work sound, trade sets by level). `PoiType(Set<BlockState>, int, int)` is a public record, but registering one also fills a private state map; Fabric's `PoiHelper.register` exists for 26.3 only, and 26.4 changes `PoiTypes`' constants to holders (F23, ADR 0077).
- `HasCustomInventoryScreen.openCustomInventoryScreen(Player)` is public on both; whether the client sends the inventory key for a ridden mob that is not a horse is open (S13).
- Shoulder riders are stored on the player as `Optional<Parrot.Variant>` (left and right) on both versions, so only parrots can be shown on a shoulder without client code (F26). Any entity can ride another through `startRiding(Entity, boolean, boolean)`, and a passenger's place comes from `getVehicleAttachmentPoint(Entity)` and the vehicle's `getPassengerRidingPosition(Entity)`, both public and identical (F26).

## Decision

- **D1 Component `msm:trader` on `msm:entity`:**

  ```
  struct Trader {
    trade_sets: [TradeLevel] @ 1..5,       // level 1 first; each names a trade set (project or vanilla)
    levels?: boolean,                       // default true: trading gives XP and unlocks the next level, as villagers
    restock?: "twice_a_day" | "never",      // default "twice_a_day", at the mob, no workstation needed
    trade_sound?: #[id="sound_event"] string, // default minecraft:entity.villager.yes (a target fact)
    on_trade?: string,                      // event; self = the mob, other = the player
  }
  struct TradeLevel { trade_set: #[id="trade_set"] string, xp_to_next?: int }   // defaults vanilla's thresholds
  ```

  Using the mob with an empty hand or any item that does not interact first (lead, name tag, saddle, spawn egg and food for breeding keep their meaning) opens vanilla's merchant menu through `Merchant` implemented by the runtime's `registry/mob/MobTrader` module on all three mob bases. Offers are drawn per level from the trade set with `TradeSet` and `VillagerTrade` (S11), saved on the mob with `MerchantOffers`' codec, with XP and level; babies, mobs that are angry or ridden, and monsters at night do not trade (a validator info on `monster` bases). The Mob Studio's Trader section writes the trade sets and their trades as ordinary ADR 0060 elements.
- **D2 Kind `msm:villager_profession`** (frozen), for vanilla villagers taking a project job:

  ```
  struct VillagerProfession {
    job_site: #[id="block"] string,          // a project block; a block that already has a POI type is refused
    trade_sets?: [string] @ 5,              // default <ns>:<path>/level_1 .. level_5, created by lowering with their tags
    work_sound?: #[id="sound_event"] string,
    requested_items?: [#[id="item"] string],
    secondary_job_blocks?: [#[id="block"] string],
  }
  ```

  The runtime registers one POI type for every state of the job site (seam `registry/PoiTypes` in `src/mc/<mc>/java`: Fabric's `PoiHelper` on 26.3; on 26.4 the approach S12 proves, reflection into the private registration in the way `Flammability` does it, or a Mixin if reflection cannot reach it, decided at B469) and the profession record; lowering adds the POI to `#minecraft:acquirable_job_site` (a mod-only tag entry, `required: false`), writes the five trade sets with tags `<ns>:<path>/level_<n>`, the lang name and the villager and zombie villager profession textures from the editor-only `textures` (`assets/<ns>/textures/entity/villager/profession/<path>.png` and the zombie villager's, where S12 shows the client looks).
- **D3 Component `msm:storage` on `msm:entity`** (mount inventories):

  ```
  struct Storage { rows?: int @ 1..6, needs_chest?: boolean, open_sound?: string, close_sound?: string }   // rows default 3; needs_chest default false
  ```

  The mob implements `HasCustomInventoryScreen` and opens vanilla's chest menu (rows) on the server when its rider presses the inventory key (S13) or when its owner (tameable) or anyone (not tameable) uses it while sneaking. With `needs_chest`, a chest used on the mob adds the storage and shows the vanilla chest-equip sound; the chest drops back with the contents when the mob dies. Contents are saved on the mob and dropped on death. Shared code with vehicles' storage (ADR 0090 D9) where both exist: `registry/mob/MobStorage` owns the menu; the vehicle batch reuses it.
- **D4 Component `msm:shoulder_riding` on tameable `animal` mobs** no wider than 0.7 blocks: a sitting-capable pet that, when its owner stands near and is not riding, jumps onto the owner and rides as a passenger at a shoulder offset (its own `getVehicleAttachmentPoint`), drawn by the mob's normal renderer (no client code, because vanilla's shoulder store holds parrots only). It leaves when the owner takes damage, sneaks, sleeps, rides, swims or flies with an elytra, and does not return for a cooldown (100 ticks). One shoulder pet per player (vetoable); a parrot keeps vanilla's own shoulder. If the spike (S13) finds a passenger on a player misplaced, shaking or lost on a dedicated server, the component is dropped from the batch before Wave 10 and recorded as a limit.
- **D5 Versions and eject.** Shared code except `registry/PoiTypes` (D2). Plugin API 1.18.0 (additive): `EntityFacts.tradeSounds?`, `EntityFacts.vanillaJobSites?` (blocks that already have POI types, for the D2 refusal), `EntityFacts.vanillaTradeSets?`. The 26.3 generator warns `export.not-in-eject` for the four components and the kind in this batch (vetoable; a follow-up).
- **D6 Not in this batch (limits).** Gossip, reputation, price changes by reputation or Hero of the Village for project traders (vanilla brain code); custom villager types (biome looks); trader mobs restocking at a workstation; wandering-trader-style despawning and llamas; project professions for zombie villagers being cured into them beyond the texture; hopper access to mount storage; more than one shoulder pet; shoulder pets that are not `animal` base; storage on vehicles is ADR 0090's.

## Consequences

- Trades stay data: a trader's offers change with `/reload` for offers drawn after it (already drawn offers are saved on the mob, as vanilla villagers').
- One more seam (`PoiTypes`) and the risk the 26.4 route carries; B469 settles it before any runtime brief.
- Mob Studio sections grow by three; the Pet, Mount and new Wandering merchant and Village job flows use them ([ADR 0101](0101-vanilla-parity-2-flows-studios-try-it-and-tests.md)).

## Amendment after the spike (B469, 2026-11-15)

- **D2 on 26.4:** settled. `registry/PoiTypes` uses Fabric's `PoiHelper` on 26.3 and reflection on the private `PoiTypes.register(ResourceKey, Set, int, int)` on 26.4; no Mixin, so reserve B487 and Q22 are closed. The runtime also refuses a job site when `PoiTypes.hasPoi(state)` is already true for any of its states, because vanilla's own duplicate check fires only after it has replaced the mapping. Lowering writes the `#minecraft:acquirable_job_site` entry (without it vanilla villagers never take the job) and all five level trade sets (missing ones fail silently). The name key is `entity.<ns>.villager.<path>`.
- **D1:** vanilla trade sets whose trades carry a `merchant_predicate` on villager variants give a project mob no offers (armourer level 5: none; librarian books and cartographer maps drop out). A validator warns about them (`EntityFacts.vanillaTradeSets` carries a villager-only flag). The runtime resends offers to an open screen after a level-up or restock.
- **D3:** confirmed as written.
- **D4 changed:** a shoulder pet is not a passenger. A player cannot be a vehicle on the server without reflection into `Entity.vehicle`, the owner's client must be sent the passengers by hand, and a riding pet is not saved. Instead the pet is **perched**: a synched and saved flag, and both sides place it at the owner's position plus the shoulder offset (`(-0.4, 1.35, 0)` turned by the body yaw; lower while sneaking) every tick, with no gravity, physics or pushing. It unperches (clearing `NoGravity` and no-physics) on the D4 events and also on a dimension change, a disconnect and the owner's death. Measured exact on the client on both versions; up to 0.063 blocks off on the server while turning.

## Findings at close (B485)

Recorded 2026-11-21 at the close of vanilla parity 2 batch 2 (B485) from the code on the session branch at 9bbbc65 and the plan's notes: B469 (f5b1610, the spike), B472 (06fb4f2), B473 (f3f892b), B474 (dab0bec), B476 (8bdfe49, e20143d), B478 (090bc3f), B479 (eb6ec8c), B480 (ddae6de, 5368101), B481 (083647c), B482 (724416f), B483 (9f8e915, e1e5b7c) and B484 (382e0f3, f16c4d4). The facts behind this ADR are F20 to F26 and F36 and its limits Q21 to Q24, kept in [ADR 0101](0101-vanilla-parity-2-flows-studios-try-it-and-tests.md)'s fact table and limits. Unreleased; awaiting the user's in-game checks (`fixtures/sample-villagers-and-fluids/README.md`).

- **Spike answers** (B469, both versions, observed in the real game; spike code deleted). S11: `VillagerTrade.getOffer` needs a `VILLAGER_TRADE` loot context with `ORIGIN`, `THIS_ENTITY` and `ADDITIONAL_COST_COMPONENT_ALLOWED` (each left out throws), random from the set's `random_sequence`; a `PathfinderMob` implementing `Merchant` opens vanilla's screen with offers, XP bar, level name and out-of-stock crosses, and level-ups and restocks reach an open screen through `sendMerchantOffers`. S12: `PoiHelper` on 26.3, reflection on the private `PoiTypes.register(ResourceKey, Set, int, int)` on 26.4; a villager takes the job only when the POI is in `#minecraft:acquirable_job_site`; pictures at `<ns>:textures/entity/villager/profession/<path>.png` and `zombie_villager/profession/`. S13: the inventory key opens `openCustomInventoryScreen` for any ridden `HasCustomInventoryScreen` mob; a player cannot be a vehicle on the server, so D4 became the perch (the amendment above). Not measured: work sounds and secondary job blocks, a villager restocking at a project job site, sleeping or gliding with a pet perched, a server stop with a pet perched (all in-game checks).
- **D1 as built** (B474, B476, B480). `loader/TraderParser` (closed) is decoded in `EntityComponents`' second codec group, because `RecordCodecBuilder` takes at most 16 fields. **Every mob body is a `Merchant`** through `MsmMob`'s default methods delegating to `registry/mob/MobTrader`: vanilla's `MerchantMenu` casts its merchant to `Entity` on a shift-click, so a separate merchant object crashed; a mob without `msm:trader` has no offers. Offers are drawn per level in the loot context of S11 and saved as `Offers`, `Xp`, `TraderLevel` and `RestockHalfDay`; the level rises at once at vanilla's thresholds (10, 70, 150, 250) or `xp_to_next` counted from the start, and the XP sent to the screen is scaled into vanilla's span of the level. Restock refills used offers once in each half of the clock day (checked every second and when the menu opens). The trade sound plays when the result slot fills, at most once a second; a shift-click gets vanilla's menu sound. The mob refuses when dead, a baby, targeting something, ridden, a `monster` at night or busy with another player; the click then passes on. Lowering fills `trade_sound` from `EntityFacts.tradeSounds`. No demand-based price rises and no hurt or level-up effects. Codes `entities.trade-set-unknown`, `trade-set-villager-only` (warning) and `trader-monster` (info).
- **Trader ids** (B480, decision). The Trader section writes a level `n` as the trade set `<id>/level_<n>` drawing every trade (`amount` = the number of trades, so traders are predictable) from the tag `#<id>/level_<n>_trades`, with trades `<id>/level_<n>/<price>_<product>`; the tag takes the `_trades` suffix because element ids are unique across kinds and the set already has `<id>/level_<n>`. The Wandering merchant flow (B481) keeps its wares in one set `<id>/wares` listing trades `<id>/ware_<n>`, then optionally vanilla's `wandering_trader/common` and `/uncommon` as levels 2 and 3.
- **The trade rebalance experiment** (B474, decision). B469's "armourer level 5 gives a project mob no offers" came from Fabric's GameTest server, which turns on every experiment: `trade_rebalance` replaces `#minecraft:armorer/level_5` with sixteen trades gated by villager type in a `merchant_predicate`. On normal worlds the B473 facts hold (only `cartographer/level_2`, `level_4` and `fisherman/level_5` are villager-only); on a world with the Villager Trade Rebalance experiment many vanilla sets give project traders fewer offers or none. The guide and the AI helper say so; `armourerLevelFiveComesFromTheTradeRebalanceExperiment` pins it on both versions.
- **D2 as built** (B474, B476, B480). `loader/ProfessionParser` (closed; default trade sets `<ns>:<path>/level_1..5`, name key `entity.<ns>.villager.<path>`) and `registry/mob/MsmProfessions`. **The POI type takes the profession's id** (as vanilla's `minecraft:armorer`), so the acquirable job site entry names the profession. **Professions register after the items** (inside `MsmRegistrar.registerAll`, not after the blocks as the plan had it), so requested items may be project items. A job site that is unknown or has any state already holding a POI is refused (the composter keeps `minecraft:farmer`; `EntityFacts.vanillaJobSites`, 21 types, drives `entities.job-site-taken`, and `job-site-unknown` asks for a project block). Lowering keeps an absent `trade_sets` absent and writes five sets drawing two trades each from empty `#<ns>:<path>/level_<n>` tags (`merge: 'tag'`) and the entry `{ id, required: false }`; it cannot copy picture bytes, so the Profession Studio copies a picture stored elsewhere to `professionTexturePaths` in the same undo step. The Village job flow writes its own trades into the level tags (optionally naming a vanilla job's tags and taking its work sound), so the default sets stay in use. `acquirable_job_site` is a constant in the plugin, not a target fact.
- **D3 as built** (B479). `loader/StorageParser`; `registry/mob/MobStorage` opens vanilla's chest menu of `rows`, saves `StorageItems` (and `StorageChest` with `needs_chest`), drops both on death, plays vanilla's chest sounds unless given others and the donkey's chest sound when a chest is put on; babies refuse chests. **Only mobs with `msm:storage` get the storage bodies** (`registry/StorageBodies`, GeckoLib twins in `GeckolibEntities`): a ridden `HasCustomInventoryScreen` mob makes the client send the inventory key to the server instead of opening the player's inventory, so a rideable mob without storage must not be one. **Storage comes first in `MobDriver.mobInteract`** (a sneaking use, or a chest on a `needs_chest` mob), so sneaking beats feeding, the sit toggle and trading, as a donkey's inventory does; a plain use still mounts or trades. Vehicles kept their own `VehicleStorage` (ADR 0090 landed first); the two share no menu code yet. Lowering writes `rows` 3 and `needs_chest` false out; `entities.storage-rows` is an info.
- **D4 as built** (B479, the amendment above). `msm:shoulder_riding` has no fields. `MobShoulder` and `MsmAnimal.DATA_PERCHED` (synched; saved `Perched`, `PerchNoGravity`, `ShoulderCooldown`) place the pet each tick on both sides at the owner's feet plus `(-0.4, height - 0.45, 0)` turned by the body yaw (the spike's 1.35 generalised by the owner's height), with no gravity, physics, pushing or suffocation. It leaves on unblocked damage (Fabric `AFTER_DAMAGE`), sneaking, sleeping, riding, water, gliding, spectator mode, a dimension change, the owner leaving or not found, and death; cooldown 100 ticks; one pet per player (a server index by owner). `goals/PerchOnOwnerGoal` walks a tamed pet not ordered to sit to an owner on the ground within 8 blocks and perches it within 1.5. On a mob that is not a tameable `animal` it logs one warning per type and never perches; `entities.shoulder-too-wide` (0.7) and `shoulder-needs-tameable` refuse it in the app. The Pet flow draws a shoulder pet at half size.
- **D5 as built** (B473, B478). Plugin API 1.18.0 `EntityFacts.tradeSounds` (`yes`, `no`, `trading`), `vanillaJobSites` (21 POI types with their blocks) and `vanillaTradeSets` (68 sets with trade counts and the villager-only flag; `wandering_trader/common` has 78 trades on 26.3 and 80 on 26.4), tied to the vendored registries and recounted from the cached client jars. Vanilla packs treat profession and POI ids as mod-only, write the job site entry `required: false` and leave out trades and sets that name a project item. The eject warns once per profession and once per mob with the three components, and strips them so the mob still ejects.
- **Tests** (B474, B479, B482). GameTests `MsmTraderGameTest` (8), `MsmProfessionGameTest` (4) and `MsmMobStorageGameTest` (8); `SampleVillagersParityTest` (15, the content jars of both versions; the trader `pedlar`, the profession `glassblower` at `glassblower_bench`, `pack_mule`, `sugar_glider`); `MsmFluidClientGameTest` shows a villager's profession picture on both versions; Try it's merchant mock-up (ADR 0101 findings).
- **Open follow-ups.** A client GameTest of the perch position on a dedicated server; one menu helper for `VehicleStorage` and `MobStorage`; `acquirable_job_site` as an `EntityFacts` entry; sim-parity scenarios for `on_trade`; villagers sleeping in project beds (no home POI yet: this seam could give them one); the D6 limits (gossip, reputation and demand prices, villager types, workstation restocking for project traders, hopper access, more than one shoulder pet); the eject of the four features.

## Status

Accepted with findings at close B485 (2026-11-21; unreleased, awaiting the user's in-game checks), with the defaults below; the user has not yet been shown them and may still veto them. B469 settled S11 to S13 before Wave 10: D2 needs no Mixin on 26.4 (reserve B487 closed) and D4 perches instead of riding. Vetoable defaults as built: a component on any mob base with vanilla's merchant menu, every body a `Merchant` (D1); levels on, restocking twice a day without a workstation, a trader's own level offering every trade it holds (D1); a profession kind with a project job site only, its POI under the profession's id, pictures at the game's paths (D2); storage opened by sneak-use and by the inventory key, 3 rows by default, sneak-use before trading (D3); shoulder pets that perch, one per player, a 100-tick cooldown (D4); no eject for this ADR's features yet (D5).
