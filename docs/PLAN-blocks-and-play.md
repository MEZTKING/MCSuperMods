# Plan: Rules, Very easy mode, one-click Play and Reload

Working plan for the user's request of 2026-11-14: "Make an easy to use, very easy to use mode using something like blueprints ... like Scratch ... anyone can build anything. Also make it easy to test, make an easier option to test whatever you build in game", clarified the same day: "it doesn't have to be scratch style. Do your own style. Just something where coding isn't necessary. Just an option for people that don't want to code." Written 2026-11-14 by the orchestrator. Decisions live in [ADR 0082](adr/0082-rules-no-code-behaviour.md) (Rules: sentence cards, the kind `msm:rules`, compilation at lowering time through project expanders, the catalogue, Script API 1.4, plugin API 1.15.0), [ADR 0083](adr/0083-very-easy-mode.md) (a third mode with Home, My things, Things to fix) and [ADR 0084](adr/0084-one-click-play-and-reload.md) (Play, the test world, runtime dev mode, Reload, Restart), all Proposed. This file holds the fact table, the rules for every brief, the briefs B362–B384 in nine waves, the interaction with the particles batch, the limits and an empty "Notes from implementation". It is deleted at close (history goes to `DEVLOG.md`, the fact table and limits into ADR 0082's and ADR 0084's findings, the other findings into their ADRs).

The file name keeps the batch's first working title ("blocks"); the user-facing feature is **Rules**, not blocks.

## Rules for every brief

- Read root `CLAUDE.md`, the scoped `CLAUDE.md` of the area, the latest `docs/DEVLOG.md` entry, this plan's "Notes from implementation", the ADRs named in the brief and, for app briefs, `docs/PLAN-particles.md`'s notes on the files you share with it. Version facts live only in `packages/targets`; engine-mod uses Mojang names, Java 25 and Fabric events over Mixins (no Mixin is planned in this batch); a 26.3/26.4 difference goes behind a seam in `engine-mod/src/mc/<mc>/` (none is expected: F3–F6 are the same on both).
- **Clean room.** Vanilla classes are read with `javap` for signatures only; no vanilla method body is copied or transcribed. Prism Launcher is called by its documented command line only.
- **Worktrees.** Each executor works in its own git worktree in the scratchpad (`<scratchpad>/wt-B<nnn>`, a unique name, from the commit the orchestrator names), builds and tests there (parallel Gradle builds in one checkout collide), commits on its own branch, does not push and does not merge. Commits carry no `Co-Authored-By`, `Claude-Session` or other credit lines and are authored as the user (HANDOFF).
- **Disk.** Check `df -h` before building. Delete your worktree's build outputs before reporting (`engine-mod/build`, `engine-mod/parity/build`, `engine-mod/.gradle`, `app/out`, `app/dist`, `node_modules/.cache`, scratch servers, stub launcher folders and ejected projects); the orchestrator removes the worktree after merging.
- **Stubs first.** The new plugin's scaffold, the lockfile change and every new GameTest and parity class are made in Wave 0 (B362), so no later brief edits `pnpm-lock.yaml`, `engine-mod/src/gametest/resources/fabric.mod.json` or `engine-mod/parity/src/main/resources/fabric.mod.json`. No brief adds a dependency (B362 adds only the scaffold's own and `typescript` as a dev dependency of the rules plugin, already in the catalog).
- **One owner per shared file per wave.** Parallel briefs in one wave never touch the same file; ownership is listed per brief. A brief that needs a file owned by another brief of the same wave stops and reports. Registration lines belong to the brief that owns the file in that wave.
- **Particles first on shared files.** The particles batch (`docs/PLAN-particles.md`, B346–B361) is in flight. A brief here that touches a file a particles brief owns starts only after that particles brief is merged; the "After" lines name them. Files shared with it: `engine-mod/.../events/EventRunner.java`, `registry/MsmRegistrar.java`, `scripting/ScriptWorld.java`, `scripting/ScriptApi.java`, `packages/plugins/scripting/api/script-api-v1.json` (B352); `studios/blocks-items/EventsEditor.tsx`, `BlockStudio.tsx`, `EffectStudio.tsx`, `studios.tsx`, `components/ElementSidebar.tsx`, `session/project-session.ts` (B353); `packages/plugins/library/src/{starters,examples}/index.ts`, `packages/exporters/test/library.test.ts`, `packages/ai/src/tools/propose.ts`, `app/test/creator-scenario.test.ts` (B354); `engine-mod/build.gradle.kts` (B356); `.github/workflows/ci.yml`, parity files (B359); guide pages, `CHANGELOG.md`, scoped `CLAUDE.md` status lines, `packages/ai/src/system-prompt.ts` (B360).
- **Notes.** Each executor ends its report with "Notes for the plan": new facts, names, signatures, labels and test ids, and what a later brief must change, with its brief number. The orchestrator appends them to "Notes from implementation" below when it merges the brief; executors do not edit this file. Each executor appends one DEVLOG entry in its commit (the orchestrator resolves append conflicts at merge).
- **Exit criteria** always include, for the touched packages: `pnpm lint`, `pnpm typecheck` and the package tests; for engine-mod `JAVA_HOME=/root/jdk/jdk-25.0.5+8 ./gradlew build` (26.3), `./gradlew build -Pmc=26.4` and `./gradlew build -PwithoutGeckolib`. App and library briefs also run `pnpm build` and `node tools/check-size/index.ts` and report `app.asar` (stop and report above 31 MB: the next reserve is gzip, ADR 0079 D4; this batch's estimate is under 0.4 MB in all). A runtime behaviour without a GameTest (or, for client code, a JUnit test or the client GameTest) is refused at review; UI without a unit test and an e2e step is refused at B379's review.
- **Plain words.** Every user-facing label is British English, no emojis, no ids in Very easy; labels go into the notes so B383 can write the guide.
- Executors: Opus (`claude-opus-5-5`) at medium effort; Sonnet (`claude-sonnet-5-5`) for B362 and B383. A stuck brief is rerun on Opus at high effort.
