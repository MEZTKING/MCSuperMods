# Live view audit

Written by brief B575 of the live world generation plan on 2026-11-22, at commit 14bfec1, and updated at that plan's close (B591, the same day; [ADR 0119](adr/0119-live-worldgen-preview.md) accepted with findings): the 14 worldgen kinds, `msm:biome_addition`, structure sets' start markers and the Creator's world flows now have a live view. It applies the standing rule **Everything visible live** ([ADR 0119 D1](adr/0119-live-worldgen-preview.md)): every kind that makes something a player can see or hear has a live view in the app (the preview panel, its Studio or Try it) that follows an edit by itself; a kind with nothing to see is exempt, with the reason. A kind without a live view is a gap here, with the batch that closes it. A brief that adds a kind, a Studio or a Creator flow adds or updates its row.

## How it was counted and checked

- **Counted from the code.** The kinds are the `contributes.elementKinds` of the ten built-in plugins that contribute kinds (`packages/plugins/*/src/index.ts`), read by loading the plugins themselves, not from any document. `@msm/plugin-library` contributes starters and examples only.
- **Live view today** comes from `previewKind` (`app/src/renderer/src/preview/PreviewPanel.tsx`: `model`, `block_definition`, `item_definition`, `structure`, `climate_map`, `worldgen_map` (since B582), `geo_model`, `animation`, `entity`, plus the `model` field of `msm:block` and `msm:item`, the armour figure and the recipe picture), the Studio registry (`studios/*/studios.tsx` and `ElementForm.tsx`'s built-in Studios, with each Studio's own Preview section), and Try it (`app/src/renderer/src/tryit/`, `packages/sim/src/`: the files each catalogue reads).
- **Checked in the running app** (`pnpm build`, then the built app under `xvfb-run -a` with SwiftShader WebGL, driven by a throwaway Playwright script outside the repository; `app/out` deleted afterwards). Copies of `fixtures/sample-worldgen` (with a dimension, noise settings, a density function and a noise added in the copy), `sample-mod`, `sample-datapack`, `sample-particles`, `sample-villagers-and-fluids` and `sample-vehicles` were opened; each element was selected and the preview panel, the editor's side preview and the Studio's preview sections were read. For a sample, the element's data was replaced through Raw JSON and Apply, and the time until the preview's text or pixels changed was measured. Try it was opened on `sample-villagers-and-fluids`. Without the client jar (as in CI), so vanilla models draw with the missing texture.
- **Measured** (time from Apply to a changed preview, SwiftShader, one run each): the climate map of a dimension 0.20 and 0.25 s; the recipe picture 16 ms; the Particle Studio preview 9 ms; the Potion Studio preview 34 and 105 ms; a block's model preview 68 and 146 ms. Try it opened in 0.76 s with the project's job block, three spawn eggs and two buckets in the hotbar, and lowers the project again 300 ms after an edit (`LOWER_DEBOUNCE_MS`, `tryit/session-source.ts`; the edits themselves are covered by `e2e/tryit-path.spec.ts`). Edits to kinds without a view (biome, noise settings, density function, noise, loot table) changed nothing on screen, as expected. A few Raw JSON replacements did not take in the script (Monaco focus), so the effect and armour rows rest on the code (both views read the element directly).
- **Verdicts.** *Has one*: a view that follows edits without a button, an export or the game. *Needs one*, with its batch: **this plan** (live world generation; none is left since its close, B591), **Live views 2: data**, **Live views 3: looks**, **Live views 4: assembled structures** (the ROADMAP ideas of the plan's section (e)). *Exempt*: nothing to see, with the reason. A row whose view covers only part of what the player sees keeps *Has one* when the main thing is shown, and names the rest in the note. Since 2026-11-22 each *Needs one: Live views 2, 3 or 4* row also names the brief of [`docs/PLAN-live-views.md`](PLAN-live-views.md) that covers it (batch 2 data B600–B618, batch 3 looks and sounds B619–B633, batch 4 assembled structures B634–B645).

## Count

**Count:** 118 kinds from the contributions (resourcepack 13, datapack 62, structures 5, worldgen 14, blocks-items 11, models-anim 2, entities 4, scripting 4, rules 1, controls 2; `library` contributes none). Has one **63**; needs one **46** (Live views 2 13, Live views 3 30, Live views 4 3); exempt **9**. Before live world generation closed (B591): has one 28, needs one 81, 14 of them that plan's. Checked in the running app: 42 kinds (marked *checked*).

## Differences from the plan's grouped reading

- `msm:effect` has a live view: the Effect Studio's Preview (icon, name in its category colour, the levels) follows edits; only the in-world look waits for Live views 3.
- `minecraft:dimension_type`, the merchant kinds (`villager_trade`, `trade_set`, `tag/villager_trade`, `msm:villager_profession`), `minecraft:lang`, `msm:command`, `msm:key_bind` and `msm:fluid` have live views through their Studios or Try it.
- `minecraft:sounds` was checked: there is no play button anywhere outside Try it.
- `msm:potion` and `msm:creative_tab` have text previews that follow edits, but not the look (bottle colour, the tab), so they stay *needs one* in Live views 3.
- `minecraft:function` was not run by Try it when this audit was written; since B613 (Live views 2) Try it runs it as far as it understands its commands and the editor marks each line.
- `msm:game_rule`, `msm:stat`, `minecraft:test_environment`, `minecraft:test_instance` and the two context providers are exempt; `minecraft:timeline` and `world_clock` go to Live views 3 (they change the sky over a day); `minecraft:block_transformer`, `trial_spawner` and `enchantment_provider` go to Live views 2.
- The contributions give 118 kinds (the datapack plugin's 62 include 21 tag kinds and 35 generic data kinds); root `CLAUDE.md` said 115 then and says 118 now. The library had 57 Creator flows then (root `CLAUDE.md` said 55) and has 62 since B586.
