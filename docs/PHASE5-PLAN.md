## Decisions (ADR drafts)

- [ADR 0028](adr/0028-entity-definition-format-v1.md): entity definition format v1 (format 1 extension of ADR 0025): `msm/<ns>/entity/<path>.json`, components `msm:health`, `msm:movement`, `msm:attack`, `msm:ai_goals` (goal subset `wander`, `look_at_player`, `look_around`, `melee_attack`, `flee`, `follow`), `msm:animated_model` (required), `msm:on_hurt`, `msm:on_death`, `msm:on_interact`, natural `spawn` rules, `spawn_egg`, action `play_animation`; the `msm:entity` element; the runtime's `MsmEntity`, GeckoLib bridge and client entrypoint; the registration log line.
- [ADR 0029](adr/0029-model-animation-pipeline.md): model and animation pipeline: GeckoLib 5.5.7 as the renderer (available for 26.3, so no fallback renderer is built), `msm:geo_model` and `msm:animation` element kinds in `@msm/plugin-models-anim`, Blockbench import in `@msm/interop` `blockbench/` (`.bbmodel` converted; `.geo.json` and `.animation.json` taken as they are) registered by the app as a host importer, the app's own small WebGL preview renderer with playback (no three.js), GeckoLib nested in the content jar only when the project has entities, fetched by the app from the Modrinth CDN with a SHA-512 check and cached.
- [ADR 0030](adr/0030-plugin-api-0.7.md): plugin API 0.7.0: `Target.geckolib` becomes `GeckolibFacts`; every built-in plugin moves to `^0.7.0`.

Fallback recorded for completeness: had GeckoLib lacked a 26.3 build, Phase 5 would have shipped a minimal own renderer in the runtime (Bedrock geometry cubes drawn with vanilla `ModelPart`s, linear keyframes) behind the same `msm:animated_model` component. It is not needed; DESIGN §17 risk 6 keeps it as the long-term fallback.

## Wave 0

### B110 — Entity and GeckoLib spike (engine-mod)

**Owns:** `engine-mod/` only (build files, `src/main`, `src/gametest`, `src/test`). Also appends findings to the "Status" sections of ADRs 0028 and 0029 (results only; do not rewrite the decisions).

**Purpose:** prove on 26.3, before any editor work, that `msm_runtime` can register a mob from `msm/<ns>/entity/*.json` at init, give it attributes, goals, a spawn egg and a natural spawn, bridge it to GeckoLib 5.5.7, and that GameTests can drive it; settle every "(verify at implementation)" item in the facts table.

**Scope:**

1. Gradle: add `maven { name = "Modrinth"; url = uri("https://api.modrinth.com/maven") }` to `engine-mod/build.gradle.kts` repositories and the dependency `maven.modrinth:geckolib:${geckolib_modrinth_version_id}` with `geckolib_version=5.5.7` and `geckolib_modrinth_version_id=kSxHvs99` in `gradle.properties`. Find the configuration that (a) compiles the runtime against GeckoLib, (b) puts GeckoLib on the GameTest server's mod list (its `fabric.mod.json`, Mixins and access widener must load), and (c) keeps GeckoLib **out of the built `msm_runtime` jar** and out of its hard `depends`. Try `compileOnly` plus a runtime-only configuration for the `gametest` run; record what works and why (Loom 1.19.3 non-remapping: `implementation` versus `modImplementation`/`modLocalRuntime`).
2. `msm_runtime` `fabric.mod.json`: add `"entrypoints": { "client": ["dev.mcsupermods.runtime.client.MsmRuntimeClient"] }` and `"suggests": { "geckolib": ">=${geckolib_version}" }` (expanded by `processResources`).
3. Scanner: accept kind `entity`. Spike parser (Gson, like B90): `format`, `category`, `size`, `components["msm:health"].max`, `["msm:movement"].speed`, `["msm:attack"].damage`, `["msm:ai_goals"].goals[]` (types `wander`, `look_at_player`, `melee_attack` only), `["msm:animated_model"]` (`model`, `animations`, `texture`, `idle`, `walk`), `spawn` (`biomes`, `weight`, `min_group`, `max_group`), `spawn_egg`.
4. Registration (`registry/MsmEntity.java`, a `PathfinderMob`; `registry/MsmEntityRegistrar.java` or inside `MsmRegistrar`): `FabricEntityType.Builder.createMob(MsmEntity::new, category, mob -> mob.defaultAttributes(...).spawnPlacement(SpawnPlacementTypes.ON_GROUND, Heightmap.Types.MOTION_BLOCKING_NO_LEAVES, Mob::checkMobSpawnRules)).sized(w, h).build(key)` registered in `BuiltInRegistries.ENTITY_TYPE`; attributes `MAX_HEALTH`, `MOVEMENT_SPEED`, `ATTACK_DAMAGE` (confirm holder names); goals added in `registerGoals` from the definition (lookup of the definition by `EntityType` through a static map filled at registration); a `SpawnEggItem` `<ns>:<path>_spawn_egg` with `Item.Properties.setId(...).spawnEgg(type)` in the `minecraft:spawn_eggs` tab; `BiomeModifications.addSpawn(BiomeSelectors.tag(...) or includeByKey(...), category, type, weight, min, max)`.
5. GeckoLib bridge: `registry/MsmGeoEntity extends MsmEntity implements GeoEntity` with one controller (`idle` loop; `walk` loop when `AnimationTest.isMoving()`); a `GeoModel` subclass returning the definition's model, animation and texture ids (texture id expanded to `textures/<path>.png`); registered **only when** `FabricLoader.getInstance().isModLoaded("geckolib")`, through a separate class (`registry/GeckolibEntities`) so that `MsmRegistrar` never loads GeckoLib types when GeckoLib is absent (check with a run without GeckoLib on the classpath: the plain `MsmEntity` registers and the definition logs one error naming the missing mod). Client: `client/MsmRuntimeClient implements ClientModInitializer` registering `EntityRendererRegistry.register(type, ctx -> new GeoEntityRenderer<>(ctx, model))` for every geo entity, guarded the same way.
6. Resources: the GameTest mod ships `msm/msm_spike/entity/glow_golem.json`, `assets/msm_spike/geckolib/models/entity/glow_golem.geo.json` (format `1.12.0`, two bones, three cubes, hand-written), `assets/msm_spike/geckolib/animations/entity/glow_golem.animation.json` (format `1.8.0`, `idle` and `walk`), a 64x64 placeholder PNG written by a test helper or checked in (made by us, no Mojang bytes), and a biome tag or key for the spawn.
7. GameTests (`gametest/MsmEntitySpikeGameTest.java`): the type is registered and is an `MsmGeoEntity` when GeckoLib is loaded; the spawn egg item exists and `SpawnEggItem.getType(stack)` is the type; a spawned mob has `getMaxHealth()` 30 and the configured speed and damage; `helper.walkTo(mob, pos, 1.0f)` followed by `succeedWhen` reaching within 1.5 blocks; with `melee_attack` targeting players, a `makeMockPlayer(GameType.SURVIVAL)` placed next to the mob loses health within 100 ticks (use `spawn` with free will, not `spawnWithNoFreeWill`); `triggerAnim("msm_triggered", "attack")` on the server does not throw; the biome of the test's level reports the spawn (read `MobSpawnSettings` or the 26.3 attribute; record which).
8.
