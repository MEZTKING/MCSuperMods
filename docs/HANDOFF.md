## How to run a phase

1. Read `DESIGN.md` sections and the ROADMAP phase; verify facts against vendored data (`vendor/`, via `@msm/schemas` and `@msm/targets`) or the upstream source (Maven Central and `maven.fabricmc.net` metadata, Modrinth API and CDN, raw GitHub, the npm registry, `javap` over the Loom-cached jars), never from memory.
2. Write a plan (`docs/PHASE<n>-PLAN.md`, deleted at close): verified facts with sources, decisions (as ADR drafts), waves of briefs. Each brief names paths it owns, scope, acceptance, out of scope. Parallel executors never share a file; one lockfile owner per wave, and the scaffolds of new plugins come in Wave 0 so later waves need no lockfile change.

## Releases

## Rules, Very easy and Play batch lessons

- **Compile, do not store twice:** rule books stay the only source and become events and scripts through a project expander at every path (validation, export, Play, eject); problems map back to the rule through patch origins, so nothing drifts and no choke point was needed on changesets.
- **One place expands:** core offers both `expandProject` and `lowerProject` with `plugins`, and passing an expanded project to the second would expand twice; B371 made the app session the single place that expands (once per project state and target) and hands the result to checks, exports and Play.
- **A stub that plays the other side finds integration bugs:** `play-path`'s stub launcher reads and writes the same status files as the runtime and found that Play sent `pack.mcmeta` files the jar leaves out, so every first data change asked for a restart. It was found after the v1.5.0 tag; the build was cancelled and the release became 1.5.1, so run the e2e paths of a batch before tagging.
- **The client GameTest route paid off at once:** the particles batch's headless route let B374 test world creation, reload, reopen and quit in CI, which the plan had expected to leave to the user (limit R5 moved).
- **Dedicated is not only real servers:** Fabric's GameTest server reports itself dedicated, so dev mode needed an explicit test switch (`-Dmsm.dev.testRoot`) and the CI server check proves the real dedicated path stays off.
- **Labels follow releases, not briefs:** Script API members labelled by the next contract number (1.5.0 to 1.8.0) all shipped in one release and had to be relabelled "Since runtime 1.5.1"; label new members with the release they will ship in, decided at close.

## Particles batch lessons

- **A time-boxed probe can open a whole test route:** B356 was allowed to fail; it found that GLX was the dead end and Mesa EGL the way, and the project now has its first automated client run (L16 narrowed), which the next client batch and B123 can reuse.
- **Probe vanilla servers for every folder a new id can reach:** environment attributes made `dimension_type` and `timeline` able to name a particle; B346's probe showed both fail the whole pack, so they joined the fatal folders before any flow wrote one.
- **A cross-language golden again tied runtime and preview:** `fixtures/particle-look/golden.json` fixed the size, step and fade rules before the Studio's preview was drawn.
- **A flaky e2e can be a real bug:** the `portals-path` flake was Save not sending held-back editor typing; the fix (flush, then atomic writes) went in mid-batch.
- **Batches overlap now:** three batches shared one branch and the counts at close include the others' tests; give the shipped batch's numbers and the totals in the tree separately.

## Portal batch lessons

- **Probe the test servers before planning tests on them:** a data pack dimension makes no level in the GameTest world, in development runs (B330) and on the production parity server (B343); the plan had assumed parity would cover the project dimension. Dedicated-server checks with `--forbid-line` now cover it.
- **Vanilla resets state every tick; read the loop, not only the setter:** an entity standing in a portal has its cooldown reset each tick by `setAsInsidePortal`, so `cooldown_ticks` had to be re-applied after it.
- **"Ground" needs a rule for fluids:** surface arrival first landed travellers on lava; the review's follow-up brief (B336b) made water ground and lava never, with GameTests, before the eject copied it.

- **Same-block portals link across concurrent tests and the GameTest world persists locally:** tests that assert a new exit clear their own index entries and put lit portals out in the same tick.

## Phase 6 lessons

- **Probe the engine before choosing the transpiler.** The plan's fact table probed Rhino 1.9.2 directly (classes, `for...of`, call spread and `async` do not parse) and esbuild's ES5 target (refuses to lower them), so the esbuild design of ADR 0003 was replaced by TypeScript's ES5 output in the plan, before any brief, instead of after a failed integration.
- **One JSON, three consumers.** `script-api-v1.json` generates the typings (golden), drives the app's checks and is compared with the runtime's installed API by a JUnit contract test; adding `require` touched all three in one change. Do the same for any surface that the app and the runtime both describe.
- **Generators belong to the target.** The Java eject names Mojang classes, so it lives in `Target.javaProject` with goldens taken from the runtime's own GameTest definitions; the exporter stays version-free.
- **Parity tests must be black-box.** The parity mod uses vanilla and Fabric API only and observes effects through `ServerMessageEvents.COMMAND_MESSAGE`; one jar holds both samples' tests, selected per run with Fabric's gametest filter. A negative run (the wrong sample) proved the tests can fail.
- **e2e finds what unit tests cannot.** The scripting spec found that Monaco 0.57 registers neither the TypeScript language id nor the completion list widget unless imported explicitly; no Monaco editor had ever shown a completion list. Unit tests with stand-in namespaces could not see it.
- **Size budgets drift late.** `typescript` in main pushed `app.asar` from 13 MB to about 24 MB of 25 MB even minified; budget checks belong in every app brief's acceptance, not only at close.
- **Load-sensitive timeouts.** App tests timed out now and then under Turborepo's parallel load; a 15 s default `testTimeout` in `app/vitest.config.ts` replaced per-test bumps.
- **Version rules need tests.** The "scripts need runtime 0.6.0" rule of ADR 0032 D4 was implicit (runtime version = app version) until B141 made it explicit (`SCRIPT_RUNTIME_MINIMUM`) and tested it.

## Phase 5 lessons worth keeping

- **Spike first, format in parallel**; the spike changes details, which go into the ADR Status sections before Wave 1.
- **Non-remapping Loom has no `mod*` configurations.** `compileOnly` plus `localRuntime` keeps an optional mod out of the built jar; `implementation` plus `include` nests a plain library (Rhino) or a mod (GeckoLib in the eject). Declare third-party Maven repositories as `exclusiveContent`.
- **GameTests with mobs and players.** `registerGoals` runs in the `Mob` constructor; `makeMockPlayer` is not in the level; `makeMockServerPlayerInLevel` is creative and fires `player.join`; `GameTestHelper.useBlock` bypasses `UseBlockCallback` (drive `ServerPlayerGameMode.useItemOn`).
- **Plugins cannot import other packages**; host contributions live in packages the app registers.
- **Executors in parallel break each other's tests for a while**; the wave's last verification is the one that counts.
- **Counts drift**: count from the plugins' contributions at close, never copy the plan's targets.
