## 2. Decisions (ADR drafts)

Next free numbers: 0063, 0064, 0065. Names and defaults marked "vetoable" are the main session's defaults.

### 2.1 ADR 0063 (draft): Potions and brewing

- **D1 Kind `msm:potion`** in `@msm/plugin-blocks-items` (no new plugin), folder `potion`, `registry: 'potion'`. Chosen over the data-only `custom_effects` route (P4) because a registry entry gives the creative tabs, `/give`, tipped arrows, loot `set_potion`, potion tags and clean chained brewing for free (P3, P5, P6).
- **D2 Runtime definition**, one file per registry entry, `msm/<ns>/potion/<path>.json` (`::msm::definition::Potion`): `{ format: 1, name?: string, effects: [{ id: #[id="mob_effect"] string, duration_ticks: int @ 1.., amplifier?: int @ 0..255, ambient?: boolean, show_particles?: boolean, show_icon?: boolean }] @ 1..8 }`. `name` defaults to `<ns>.<path>` (dots keep two mods apart, P4).
- **D3 Element (editor) fields, stripped in lowering:** `display_name`; `brewing?: { base?: potion id (default `minecraft:awkward`), reagent: item id or tag }`; `long?: { duration_ticks, reagent? (default `minecraft:redstone`) }`; `strong?: { amplifier, duration_ticks, reagent? (default `minecraft:glowstone_dust`) }`; `splash?`, `lingering?: boolean` (default true). Lowering writes up to three definitions (`<path>`, `long_<path>`, `strong_<path>`, sharing `name`), the brewing recipes in vanilla's shape under `data/<ns>/recipe/brewing/` (base, long and strong for each bottle kind; gunpowder and dragon breath per entry; at most 15 files), and four `en_us` keys ("Potion of X", "Splash Potion of X", "Lingering Potion of X", "Arrow of X"). Tipped arrows need no file (P5).
- **D4 Runtime.** `DefinitionScanner.KINDS` gains `potion`; `MsmRegistrar` registers potions after effects and before blocks and items, so an item's `minecraft:potion_contents` passthrough may name a project potion without `DELAYED`. An unknown effect id is an error and that potion is skipped. `LoadReport` and the start-up line count potions. Registry freeze as for effects (L1).
- **D5 Getting the potion** is vanilla: brewing stand, creative tabs, `/give`, loot. No custom bottle item, no instant effects, no custom colour (the colour is the effects').
- **D6 Vanilla packs.** The definition is in the `msm` layer (`export.layer-skipped`); the recipes are data and name an unregistered potion there (P8). The app warns (`blocks-items.potion-needs-jar`, on vanilla pack export only, wording as ADR 0050). A potion of vanilla effects lowered to `custom_effects` for vanilla packs is deferred.
- **D7 Plugin API 1.9.0 (additive):** `JavaProjectInput.potions?: DefinitionInput[]` ("Since 1.9.0"); the `java-project` exporter routes `msm/<ns>/potion/`. Shared with ADR 0064 D5.
- **D8 Java eject (26.3 generator):** `ModPotions.java`, called after `ModEffects`; recipes and lang are files already.
- **D9 App.** Potion Studio (effects list, variants, brewing chain shown as steps, names preview); project potions, with the `long_` and `strong_` ids, count as `potion` ids in completion and validation; Effect Studio gets "Make a potion", which adds an `msm:potion` for that effect in one undoable change.
- **D10 Creator.** Flow **Potion** (group "Magic"): name, effect (own or vanilla), time, level, ingredient, longer and stronger versions, splash and lingering. The Status effect flow's "how players get it" gains "A brewed potion". Two templates, two examples.
- **D11 Versions.** Shared runtime code, no seam expected (P1 to P6 identical on 26.4); eject 26.3 only, as today.
- **D12 Deferred:** brewing items that are not potions, brewing stand fuel (`BrewingFuel` component), a Recipe Studio brewing layout, a check against vanilla ingredient pairs (needs recipe facts in the target), other mods' effects registered after ours.

### 2.2 ADR 0064 (draft): Data kinds sweep

- **D1 Worth it, as generic kinds** (`GENERIC_DATA_REGISTRIES`, schema `resource:<name>`, one default each, K1, K2): the seven mob variants and five sound variants, `instrument`, `enchantment_provider`, `trial_spawner`, `timeline`, `world_clock`. Sixteen kinds, files only, valid in vanilla packs.
- **D2 Resource pack:** kinds `minecraft:atlas` and `minecraft:font` in `@msm/plugin-resourcepack` (folders exist, K5); one template "Icon font" (bitmap provider over a project texture).
- **D3 Tags:** the eight registries of K4 join `TAG_REGISTRIES`.
- **D4 Not worth it now** (stated so nobody expects them): `sulfur_cube_archetype` (differs per version), `test_environment`, `test_instance`, `block_transformer`, the two context providers, `slot_source`, 26.4-only `block_sound_set` and its tag (wait for the 26.4 re-pin), shaders, post effects, waypoint styles, particle definitions (B14).
- **D5 Plugin API 1.9.0 (additive):** `DataFolderKey` gains the sixteen keys; both targets gain the folders. `ResourceFolderKey` is unchanged.
- **D6 Creator flows, data only.** **Mob skin** (group "Mobs"): animal (wolf, cat, pig, cow, chicken, frog), textures (tinted placeholders of the right size; Picture to texture as elsewhere; never a Mojang file), where it appears (chosen biomes with a higher priority, or everywhere mixed in). **Goat horn** (group "Gear"): sound (a project sound as `{ sound_id }`, ADR 0057 D4, subject to K3), length, range, a recipe whose result is `minecraft:goat_horn` with the `minecraft:instrument` component, optionally the `regular_goat_horns` tag so goats drop it.
- **D7 Templates:** one each for wolf variant, cat variant, instrument, trial spawner, two brewing recipes (P7); none for the rest (asar budget, L15).
- **D8 No runtime and no eject change.** `minecraft:instrument` in `ComponentPassthrough.DELAYED` (L14) is deferred: the recipe route needs no code. The proof that the files load is the headless vanilla data pack check.

### 2.3 ADR 0065 (draft): Script API 1.1

Additive: `version` stays 1, every existing member keeps its meaning, and the JSON, the typings golden and `ScriptApi` change in one push (`ScriptApiContractTest`). "1.1" is a documentation name; new doc strings say "Since runtime <release version>". Amends ADR 0032.

- **D1 Items.** `ItemRef` (still a copy) gains `name`, `maxCount`, `damage`, `maxDamage`, `hasComponent(id)`, `getComponent(id): unknown` (the component's codec output as a JSON value). New `ItemSpec = string | { id, count?, components? }` (components decoded with `DataComponentPatch.CODEC`, applied validated); `Player.give` accepts it.
- **D2 Inventory.** `Player.inventory: Inventory` with `size`, `selectedSlot`, `get(slot)`, `set(slot, item?: ItemSpec)`, `count(item)`, `remove(item, count?): number`, `find(item): number`, `setComponent(slot, id, value?)` (undefined removes). A slot is 0 to 35 or `"mainhand" | "offhand" | "head" | "chest" | "legs" | "feet"`. Every living entity: `Entity.equipment(slot): ItemRef | undefined`, `Entity.setEquipment(slot, item?)`.
- **D3 Player state.** `xpLevel`, `xpPoints`, `food`, `saturation`, `gameMode` (read); `addXp(points)`, `addXpLevels(n)`, `setXpLevels(n)`, `setFood(level, saturation?)`, `setGameMode(mode): boolean`. Each write has a test that the client is told (audit section 2.3).
- **D4 Screen text.** `Player.showTitle(title, options?: { subtitle?, fadeIn?, stay?, fadeOut? })`, `showActionBar(text)`, `clearTitle()`. `msm.bossBars.create(id, { title, color?, style?, progress? }): BossBar` and `get(id)`; `BossBar`: `setTitle`, `setProgress`, `setColor`, `setStyle`, `addPlayer`, `removePlayer`, `players()`, `remove()`. Bars belong to the script's namespace, at most 32 per namespace, are not saved, and are removed on `/reload` and stop (as `msm.schedule`).
- **D5 Damage.** `Entity.damage(amount, options?: { type?: damage type id, attacker?: Entity, direct?: Entity })`; without options it stays generic. An unknown type is a script error. Closes L12.
- **D6 Raycast.** `World.raycast(from, direction, maxDistance, options?: { fluids?, entities?, ignore? }): RayHit | undefined` and `Entity.raycast(maxDistance, options?)` from the eyes along the look; `RayHit { kind: "block" | "entity", pos, distance, block?, face?, entity? }`; more than 128 blocks is a `RangeError`.
- **D7 Teleport and worlds.** `Entity.teleport(pos, options?: { dimension?, yaw?, pitch? })`; `msm.getWorld(dimension): World | undefined`; `msm.players(): Player[]`. A wrapper stays valid after a cross-dimension move (non-players are re-created by vanilla; resolve by UUID).
- **D8 Events.** `player.tick` (`ServerTickEvents.END_SERVER_TICK`; `on("player.tick", fn, { interval? })`, default 20, minimum 5 ticks as ADR 0061 D4, staggered by entity id, counted by the shared limiter), `player.respawn`, `player.leave`, `player.changeDimension` (`from`, `to`), `player.chat` (cancellable, `message`), `entity.damaged` (after damage, final `amount`). `EntityHurtEvent` gains `source` (damage type id) and `direct`.
- **D9 Limits.** Component values pass through `ScriptJson` (depth 128) and at most 64 KiB per call; the 2000 ms budget is unchanged.
- **D10 Tests and parity.** Runtime GameTests for every member; `SampleScriptParityTest` on the content jars of both versions (no ejected half, ADR 0058 D4).
- **D11 Deferred:** `block.place` (A5: no event without a mixin; project blocks have `msm:on_place` with `run_script`), changing the damage amount in `entity.hurt` (A5), `msm.commands.register` (command tree and reload order need a spike), custom creative tab (a definition feature, not script), dropped items and projectiles in `entitiesNear`, client-side anything (L2).
