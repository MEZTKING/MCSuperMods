# tools

Development scripts for the MSM monorepo (`@msm/tools`). Every script is TypeScript run directly by Node (>= 22.18 strips types), so each uses only erasable syntax, `node:` imports and explicit `.ts` import extensions. Tests run with `pnpm --filter @msm/tools test`.

| Folder | Command | Purpose |
|---|---|---|
| `build-msm-mcdoc/` | `node tools/build-msm-mcdoc/index.ts [--check]` | Exports the MSM mcdoc in `packages/schemas/mcdoc/msm/` to its checked-in `symbols.json`; `--check` fails when it is stale. See its README. |
| `check-deps/` | `node tools/check-deps/index.ts` | Enforces the package layer map (`layers.json`) and rejects Minecraft version literals outside `packages/targets`, and checks that `engine-mod/parity/gradle.properties` has the same Minecraft, Loader, Loom and Fabric API versions as `engine-mod/gradle.properties`. Part of `pnpm lint`. |
| `check-project/` | `node tools/check-project/index.ts <project folder>... [--target <id>\|all] [--json]` | Opens MSM project folders with the app's own session, upgrades them to each target as Upgrade project target does, runs every validator and exports the resource pack, data pack and Fabric mod jar; refuses files that look like Mojang assets and oversized files. Used by the community repository's CI; see its README. |
| `check-size/` | `node tools/check-size/index.ts` | Size budgets for `app.asar` and the renderer output, run in CI after `dist:dir`; see its README. |
| `community-repo/` | `node tools/community-repo/sync.ts --repo <folder> [--check]` | Writes the community repository's `examples/` (projects, pictures, READMEs and the index) from the `examples/` mirror; `--check` fails when it is out of date. See its README. |
| `diff-targets/` | `node tools/diff-targets/index.ts --from <target folder> --to <target folder> [--out <file>] [--draft <file>] [--check]` | Diffs two targets' vendored data (registries matched by overlap, mcdoc gated or by two refs, commands, block states, `version.json`) into the generated change set of ADR 0136, with rename and field-move candidates; pure and offline. See its README. |
| `new-plugin/` | `node tools/new-plugin/index.ts <name>`; `node tools/new-plugin/index.ts <name> --external <dir>` | Scaffolds `packages/plugins/<name>` as `@msm/plugin-<name>`, or with `--external` a standalone third-party plugin project (`msm-plugin-<name>`: manifest, esbuild bundle, mcdoc export) in `<dir>`; see its README. |
| `new-target/` | `node tools/new-target/index.ts --from mc-<a> --version <new>`; `--repin mc-<b> --version <new>`; `--check`; `--dry-run [--out <dir>]` | Makes a target folder from the newest one or re-pins one: runs the sync tools and `diff-targets`, recomputes the derived facts, drafts the Fabric and Java facts and writes `VERIFY.md` (ADR 0136 D11); `--check` says whether Mojang has a newer version than each target. See its README. |
| `run-fabric-server/` | `node tools/run-fabric-server/index.ts --jar <jar> --facts <file>` | Starts a headless Fabric dedicated server with a content jar and checks the `msm_runtime` registration log (ADR 0026 D6); with `expectEntities` it also checks the `registered K entity type(s)` line, with `expectScripts` the `loaded S script(s); 0 error(s)` line, and `--separate-geckolib` downloads GeckoLib (SHA-512 checked) for a jar without it nested. `--gametest <jar>` runs a GameTest mod (the parity tests in `engine-mod/parity/`) on a production GameTest server and checks its report, `--gametest-filter <selector>` picks its tests; `--no-runtime` checks a jar without `msm_runtime` (ejected projects). CI runs it on `fixtures/sample-mod`, `fixtures/sample-mob` and `fixtures/sample-script`, and runs the parity tests on both samples' content and ejected jars. See its README. |
| `sync-mcdoc/` | `node tools/sync-mcdoc/index.ts --ref <sha> --out <dir>` | Vendors the vanilla-mcdoc symbol export for a target; see its README. |
| `sync-mcmeta/` | `node tools/sync-mcmeta/index.ts --version <version> --out <dir>` | Vendors mcmeta version and registry data for a target; see its README. |
| `sync-feature-order/` | `node tools/sync-feature-order/index.ts --version <version> --out <file>` | Vendors vanilla's placed feature order per decoration step (ids only) from mcmeta's biome summary for a target's `vanillaFeatureOrder` fact (ADR 0097 D1); see its README. |
| `shared/` | (library) | Download, strict JSON and atomic-write helpers shared by the sync scripts, and `workspace-hooks.ts`, the module hooks that let Node run the workspace's TypeScript sources (imports without endings, `?raw`). |

## Layer map

`check-deps/layers.json` lists, per package name or glob, the internal `@msm/*` packages it may depend on. An exact key wins over a glob, so `@msm/targets` (the aggregator in `packages/targets/all`) is not governed by `@msm/target-*`. Plugins, exporters and interop may depend on `@msm/targets` for tests only; Biome overrides in the root `biome.json` forbid importing it from plugin and exporter `src/`.
