# community-repo

Keeps the `examples/` folder of the [MCSuperMods community repository](https://github.com/MEZTKING/MCSuperMods-Community) in step with MSM's own `examples/` mirror (generated by `packages/exporters/test/library.test.ts`).

```sh
node tools/community-repo/sync.ts --repo <community repository> [--examples <MSM examples folder>] [--check]
```

- `--repo` is a checkout of the community repository. Only its `examples/` folder is written.
- `--examples` defaults to this repository's `examples/`.
- `--check` writes nothing and fails (exit 1) when the community `examples/` differs from what the sync would write, listing the first differences. The community repository's CI runs it against a checkout of MCSuperMods `main`.

## What it writes

Each mirror project (a folder holding `msm.project.json`) becomes `examples/<the same path>/` with:

- the project files (`msm.project.json`, `content/`, `assets/`), byte for byte;
- `picture.png`: the first of the project's own textures that is not empty (item pictures first, then block pictures, then any other), enlarged by a whole number to at most 128 pixels without smoothing; the first frame of an animation strip. A project without a texture gets a picture drawn by the library's art generator (a green leafy block for a world or worldgen project, a blue gem otherwise);
- `README.md`: the title, the picture, the description, the category, the target and its Minecraft version, the licence (MIT, like MCSuperMods), the member examples of a grouped project, and how to open it.

`examples/README.md` indexes every example by category. Files the sync no longer makes are removed, so it is idempotent: a second run changes nothing.

The README text comes from the library (`@msm/plugin-library`): `popular/<folder>` from `popularExamples` (`popularFolder`), `worlds/<name>` from `worldExamples`, `starters/<id>` from `libraryStarters`, and the grouped projects (`all-kinds`, `blocks-items`, `entities`, `scripts`, `rules`) from the same lists `library.test.ts` builds them from, with a category and description of their own in `examples.ts`. A mirror folder that matches none fails the sync, so a new kind of mirror folder is noticed.

The community repository's check of shared mods can show what a newer Minecraft would ask of each one (ADR 0136, B824): `node tools/check-project/index.ts <mod folder>... --upgrade-report` prints the report in plain words (or `--json`), exits 1 when a mod needs something changed by hand, and writes nothing.

Like `check-project`, `sync.ts` registers `tools/shared/workspace-hooks.ts` first so Node can load the workspace packages.

## Files

| File | What it holds |
|---|---|
| `sync.ts` | The entry: registers the hooks and runs `run.ts`. |
| `run.ts` | Reading the trees, writing or checking, the command line. |
| `examples.ts` | The library entry of each folder, the READMEs and the index. |
| `picture.ts` | Choosing, reading and enlarging the picture. |
| `community-repo.test.ts` | Tests (`pnpm --filter @msm/tools test`). |
