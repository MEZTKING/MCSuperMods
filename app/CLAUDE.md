## Purpose

`@msm/app`: the Electron desktop shell that hosts editors, Studio views and previews over the `@msm/core` IR.

## Conventions

- No business logic in the app: it lives in `@msm/core` and plugins.
- All OS access goes through the `PlatformAdapter` interface (keeps a Tauri port possible).
- IPC is typed and versioned; binary payloads are `Uint8Array`.
- The Claude SDK runs only in main (Biome forbids `@anthropic-ai/sdk` and `@msm/ai/sdk` in the renderer and preload); the key never leaves main.
- Spyglass and the `typescript` compiler run only in main; Biome forbids `@spyglassmc/*` and `@msm/schemas/mcfunction` in the renderer (the Script Studio uses Monaco's own TypeScript worker).
- Every Monaco editor (JSON, function, script) binds through `bindControlledModel` (`json-editor/controlled-model.ts`): ignore the editor's own echoes, apply external changes with `pushEditOperations`.
- Lazy-load Monaco and the 3D preview; budgets in `tools/check-size` (DESIGN §14; `app.asar` 32 MB, at 27.2 MB; renderer total 21 MB (at about 18.8 MB) and first paint 6 MB (at about 4.7 MB); stop lines 31, 20.5 and 5.5 MB, ADRs 0123, 0126 D4; vendored target data gzipped, deepslate tree-shaken by `DEEPSLATE_SIDE_EFFECTS` in `electron.vite.config.ts`; the TypeScript worker a separate `ts.worker` chunk). Extra Monaco workers register through `registerWorker` in `monaco-setup.ts`.
- CSP: scripts `'self'` only; `style-src 'unsafe-inline'` for Monaco/Radix; `img-src data:` for thumbnails; `worker-src 'self' blob:`; `media-src 'self' blob:` for streamed sounds (ADR 0121, B622).
- Game locations: installs write only inside the selected `gameDir` (real-path containment: game dir in instance, instance in instances root); `location.game-dir-missing` blocks install, version mismatch only warns. Launcher path and file-format facts stay in `@msm/interop` `launchers/`.
- Asset removal moves bytes to `.msm/trash/` so undo restores them; bytes replaced through `applyChangeset({ writes })` (the Creator's Update) are kept in `.msm/undo/` and restored by the same Undo (`app.asset-write` command effects, ADR 0045); both empty on open/create.
- Releases are Windows only (NSIS x64, unsigned); the updater is active only when packaged on Windows outside test runs. Every release needs a user-facing `CHANGELOG.md` section (`## [x.y.z] - YYYY-MM-DD`): `release.yml` uses it as the release body, and `test/components/WhatsNew.test.tsx` checks the app version has one.
- British English in UI text and docs; no emojis. Accessibility: keyboard navigation, labelled controls.

## Do / Don't

- Do keep Studio views thin over the IR; Raw JSON and Studio edit the same element.
- Don't import from `packages/plugins/*` internals; go only through the plugin registry.
- Don't add template, starter or example content here: it belongs in the plugins (ADR 0020).
- Don't hard-code version facts (recipe categories, ids); read them from the schema.
- Don't touch Minecraft assets outside the extraction cache (`~/.msm/cache/assets/<version>/`, ADR 0011).
- Known gaps: F2 in Monaco on Windows (unchecked); the live world map draws no carved caves or structure pieces and its Height view takes 3.4 to 3.9 s (ADR 0119 limits WL1–WL18); the data views' limits are ADR 0120's 2L1–2L12 (one roll is MSM's own, the advancement layout and dialogs about right, functions run as far as Try it understands them) and the looks' ADR 0121's 3L1–3L12 (Minecraft's sounds need the Minecraft folder, bodies are MSM's stand-ins, core shaders a compile check); structure blocks are not editable in-app; only the first random palette is read.
- UI labels named in `docs/guide/` must match the code; update the guide when one changes.

## Commands

- `pnpm dev`, `pnpm --filter @msm/app test` (from the repository root); `pnpm --filter @msm/app smoke | e2e | dist:dir | smoke:packaged | dist` (headless: `xvfb-run -a`).
- `node tools/check-size/index.ts` after `pnpm build` and `dist:dir`.
- Env: `MSM_HOME` (settings and cache root), `MSM_SMOKE=1`, `MSM_E2E_PROJECT_DIR`, `MSM_E2E_OUT_DIR`, `MSM_E2E_PICK_FILES`, `MSM_E2E_AI_SCRIPT` (absolute path of an `AiModelScript`: scripted model, key reads as set `…e2e!`), `MSM_E2E_RUNTIME_DIR` (runtime jar folder in place of `engine-mod/build/libs/`), `MSM_E2E_NEW_INSTALL=1` (keep the launch notice, so a fresh `MSM_HOME` gets the Welcome in Very easy), `MSM_E2E_AI_PICTURES_FAKE=1` (a fake image service in main: no key, no network) (any `MSM_E2E_*` disables the updater).
